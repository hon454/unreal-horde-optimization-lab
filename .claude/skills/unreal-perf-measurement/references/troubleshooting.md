# 측정과 패키징의 문제

측정이나 패키징이 이상할 때 연다. 증상으로 찾는다. 예시 수치는 `SKILL.md` "예시 수치의 조건"에서 잰 참고값이다.

| 증상 | 대처 |
| --- | --- |
| Test 패키지에서 `stat anim`, `ProfileGPU`, 디버그 드로우 CVar가 동작하지 않는다 | 정상이다. Test에서는 컴파일되지 않는다(`tracing.md` "Test 구성에서 되는 것"). 그 화면은 Development 빌드로 따로 찍고 수치는 비교에 쓰지 않는다 |
| 벤치마크가 실패했는데 프로세스 종료 코드가 0이다 | Windows에서 게임의 비강제 종료(`FPlatformMisc::RequestExitWithStatus(false, 코드)`)는 `PostQuitMessage`만 부르고 그 코드가 프로세스 종료 코드에 닿지 않는다(`WindowsPlatformMisc.cpp`, `Launch.cpp`). 실패는 CSV 메타데이터의 성공 표시와 CSV 유무로 판정한다. 강제 종료(`RequestExitWithStatus(true, 코드)`)만 0이 아닌 코드를 낸다 |
| 캡처한 파일이 `.csv.bin`이라 스크립트가 읽지 못한다 | 압축된 CSV다. 캡처 전에 `csv.CompressionMode 0`을 건다(`protocol.md` "캡처") |
| 쿡이나 에디터 실행 뒤 `Config/DefaultEngine.ini`가 바뀌어 빌드가 커밋되지 않은 변경을 가진다. 절 머리 앞에 빈 줄이 생기고 `AndroidFileServerRuntimeSettings` 절과 새 `SecurityToken`이 더해진다 | 기본으로 켜진 `AndroidFileServer` 플러그인이 토큰을 만들어 저장한 것이다. Android를 쓰지 않으면 `.uproject`에서 이 플러그인을 끈다(`"Enabled": false`). 토큰이 든 절은 비밀 값이라 커밋하지 않는다. 바뀐 파일은 되돌린다 |
| 빌드가 DLL 잠금으로 실패한다 | 에디터나 게임 실행이 떠 있다. 닫고 다시 빌드한다. 측정 중이면 측정이 끝날 때까지 빌드하지 않는다 |
| 주기적인 스파이크(예: 7초 주기)가 프레임 p95를 흔든다 | 브라우저 같은 백그라운드 프로세스의 CPU 버스트다(참고값). 닫고 다시 잰다. 프레임 p50의 2배를 넘는 프레임들의 간격이 일정한지 보면 주기성을 확인할 수 있다. 주기적이면 그 묶음을 "참고"로 내린다 |
| 같은 조건에서 가끔 한 실행이 프레임 p95 약 0.5ms 길다 | 원인 미확정. 게임 안의 일은 늘지 않았고 CPU 쪽이 고르게 느려졌다(참고값). 느린 실행 규칙으로 다시 잰다(`judging.md` "느린 실행"). CPU 클럭을 실행마다 남겨 가린다 |
| 같은 조건의 실행들이 프로세스마다 다른 수준으로 흩어진다(실행 안은 평탄) | 측정 중에 에디터나 다른 무거운 프로세스가 떠 있었다. 그 묶음은 버리고 그 프로세스 없이 다시 잰다(`protocol.md` "재는 동안의 PC") |
| 게임 스레드 시간이 다른 실행보다 10% 넘게 길다 | 게임 창이 앞 창이 아니었는지 본다. 뒤에 있던 실행은 약 12% 길었다(참고값, 2만 개체). 그 실행은 실패로 처리한다 |
| 오래 비워 둔 묶음의 뒤쪽 조건이 모두 느려졌다 | 모니터가 꺼지거나 유휴 유지 관리가 돌았다. 화면 끄기를 "안 함"으로 두고 뒤쪽 실행을 다시 잰다 |
| 프레임 수가 너무 적어 실행이 버려진다 | 프레임이 아주 긴 조건이다. 예: 프레임당 400\~470ms면 10초 창에 30프레임이 안 된다(참고값). 측정 창을 늘리거나 그 조건을 "참고"로 둔다. 프레임이 0.4초를 넘으면 엔진이 델타를 잘라 일이 달라진다는 점도 함께 적는다(`equivalence.md`) |
| 지난주에 잰 값과 오늘 잰 값이 같은 조건인데 다르다 | 다른 묶음의 값끼리는 견주지 않는다. 필요한 조건을 같은 빌드, 같은 묶음에서 다시 잰다(`judging.md` "참고로 내리는 비교") |
