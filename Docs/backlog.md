## 글 대기열

마일스톤 완료 시 항목을 더한다. 글은 최신 main에서 `Posts/NN-이름/`에 쓴다(수치는 가장 최근 전체 묶음, AGENTS.md "진행 방식"). 번호는 독자 순서다(마일스톤 번호와 다를 수 있다). 틀은 [posting.md](Guides/posting.md).

글은 목표 사양에서 출발해 사다리를 따라가는 순서로 쓴다(2026-11-11 사용자 결정, [plan.md](plan.md) "품질 계획"). 글마다 "이 단계가 사거나 버는 것 → 바꾼 것 → 목표 총수에서 잰 값과 빼 보기 표의 행"을 쓰고, HUD를 켠 촬영 실행의 GIF를 하나 넣는다. 효과가 없던 실험도 경위로 싣는다. 글에는 한계보다 프로젝트의 목적을 적는다: 호드 1만을 60fps로 돌리면서 거리별로 품질을 확보하는 방법을 단계마다 수치로 보이고, 장면은 평지로 고정해 기법 하나의 비용과 이점만 드러나게 했다.

글을 쓰기 전에 [post-review.md](post-review.md)를 본다(핵심 인사이트, 글별로 쓸 재료와 버릴 재료, 틀린 문장). 경위에는 수치를 쓰지 않는다([posting.md](Guides/posting.md) "본문과 측정 기록").

**글의 수치는 총괄 묶음에서 만든다(2026-11-10 사용자 결정, [ADR-0006](Decisions/0006-three-measurement-tiers.md)).** 총괄 묶음 `Full1`은 평지 시나리오에 체력 분산을 더한 조건에서 잰다(2026-11-11 사용자 결정, ADR-0009). 그전의 묶음은 설계 판단의 참고로만 쓰고 글의 수치와 근거로 쓰지 않는다.

글에 넣을 것(사용자 요청, 2026-11-07). 질답에서 나온 설명할 부분은 [post-material.md](post-material.md)에 모은다:
- Lumen을 끄거나 미니언을 Lumen에서 뺀 경우, Lumen이 무엇인지 짧게 설명하고 시험 중 Lumen이 프레임 저하를 일으켜 그렇게 했다는 경위를 쓴다. 근거 수치: M1 N=2000 Test 패키지 시험에서 미니언 ISM이 Lumen에 참여하면 GPU 29.0ms, 제외하면 5.3ms, Lumen 전체를 끄면 4.0ms(`Saved/Profiling/CSV/trial/`, 비교 수치가 아닌 시험 실행). 정식 수치는 그 글의 `measurements.md`에 다시 잰 값으로 둔다.
- 엔진 Mass ISM은 기본으로 그림자를 그리지 않는다(`FMassStaticMeshInstanceVisualizationMeshDesc::bCastShadows = false`). M0 액터와 맞추려고 켰다는 것.
