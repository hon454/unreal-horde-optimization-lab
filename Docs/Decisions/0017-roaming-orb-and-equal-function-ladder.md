# ADR-0017 떠다니는 오브 시나리오와 기능이 같은 사다리로 다시 만든다

- 상태: 승인됨(2026-11-14 채팅에서 사용자가 승인)
- 날짜: 2026-11-14

시나리오와 시뮬레이션을 `v2` 브랜치에서 다시 만든다. 오브는 호드 위를 정해진 궤도로 떠다니고, 사다리의 모든 단계는 같은 기능(서로 겹치지 않기, 가까운 액터의 캡슐 콜리전)을 한다. 측정 장치(러너, CSV, 요약, 그림, 사이트)는 그대로 쓴다. 이렇게 하면 최종 구성의 기법이 고정 목표 전제에 기대지 않고, 게임 스레드 수치가 기능을 덜어 낸 하한값이 아니게 된다. 대신 실행 간 편차가 커질 수 있고, 목표 사양(호드 총수 1만, 60fps)을 다시 정해야 할 수 있다.

## 맥락

2026-11-14에 구현, 시나리오, 측정 방법을 세 관점(정석 구현, 실무 과정, 시나리오 특수화)으로 점검했다. 사용자는 구현을 모두 바꿀 수 있다는 전제에서 가장 좋은 포트폴리오이자 실험실을 목표로 삼았다.

| 사실 | 근거 |
| --- | --- |
| 200m 밖 자체 이동과 엔티티 구동 입자는 고정 목표로 등속 직진하는 호드를 전제로 한다 | `ULabOffMoveProcessor`, `LabCrowdFxProcessor.cpp` |
| ISKM 고정 바운드는 오브와 카메라가 자리를 옮기지 않는 것을 전제로 한다 | [Worklog/M5.md](../Worklog/M5.md) |
| 카메라는 제자리 회전만 한다. 거리 구간을 넘나드는 전환 비용은 재지 않았다 | [measurement.md](../Guides/measurement.md) "확정값" |
| 하이드레이션 액터는 콜리전과 이동 컴포넌트가 없다. 캡슐을 켜면 호드 1만 P1의 프레임 p95가 11.49ms에서 12.91ms가 된다 | `Measurements/Full3/summary.csv`의 `L8`, `S8-col` |
| 미니언은 서로 비켜 가지 않는다. 엔진 회피 프로세서는 2만 P1에서 프레임 p50을 10.6ms 늘렸고 원인 프로세서를 확인하지 못했다 | [Worklog/M4.md](../Worklog/M4.md) |
| 액터 동기화와 ISKM 갱신을 직접 짠 근거는 Worklog에만 있고 사다리의 단계로 재지 않았다 | [Worklog/M5.md](../Worklog/M5.md), [engine-notes.md](../Reference/engine-notes.md) |
| 저격 대상 선택의 해시는 틱과 무관하게 가장 작은 일련번호를 뽑는다 | `LabMassProcessors.cpp`의 `HashCombineFast` 호출, 엔진 `TypeHash.h`의 `HashCombineFast` |
| Lab 프로세서는 `World->GetSubsystem`과 `FScopeLock`으로 공유 상태에 접근한다. `AddSubsystemRequirement` 선언은 ISKM 프로세서 한 곳뿐이다 | `LabMassProcessors.cpp` |

## 결정

1. 작업은 `v2` 브랜치에서 한다. main은 태그 `v1`의 상태로 동결하고, 전 조건 측정과 글·README·사이트 교체가 끝난 뒤 병합한다. 그때까지 `gh-pages`는 건드리지 않는다.
2. 측정 장치(러너, CSV 스키마, 요약, 그림, 사이트)는 유지한다. [ADR-0002](0002-freeze-measurement-infra.md)의 동결은 `v2`의 첫 총괄 묶음 직전에 다시 건다.
3. 오브는 호드 위를 닫힌 궤도로 떠다닌다. 궤도는 시드로 고정한다. 카메라는 오브를 따라간다. 측정 구간은 궤도 한 바퀴의 정수 배다.
4. 장면은 평지다. 장애물과 경로 탐색은 넣지 않는다.
5. 사다리의 모든 단계는 같은 기능을 한다: 움직이는 오브를 쫓기, 서로 겹치지 않기, 가까운 액터의 캡슐 콜리전, 피해와 사망. 각 단계는 같은 일을 더 싸게 하는 것만 바꾼다.
6. 첫 Mass 단계는 엔진 프로세서를 그대로 쓴다. 직접 짠 구현으로 바꾸는 것은 트레이스로 병목을 보인 뒤의 별도 단계다.
7. 최종 구성과 그 빼 보기에는 정지 조건(궤도 속도 0)을 하나 붙인다. 사다리는 이동 시나리오로만 잰다.
8. 저격 대상 해시와 서브시스템 접근 선언을 고친다.
9. 궤도 속도, 피해 반경, 목표 총수, 사다리의 단계 목록은 시험 실행의 값(A/A 편차, 가까운 개체 수)을 보고 사양 문서와 계획 문서에서 정한다. 구현은 두 문서와 상세 계획안이 확정된 뒤에 시작한다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 구현만 정석화하고 시나리오는 고정한다 | 예상되는 수치 변화가 거의 없다. 세 기법의 전제가 한계 문장으로만 남는다 |
| 장애물과 경로 탐색까지 넣는다 | 맵 제작과 내비게이션 비용이 들어와 변수가 "개체 수와 거리"를 벗어난다. [ADR-0008](0008-game-scene-baseline-and-target-spec.md)을 버린 이유와 같다 |
| 기능 없이(겹침, 판정 없는 액터) 오브만 움직인다 | 게임 스레드 수치가 하한값이라는 약점이 남는다. 뭉치는 장면에서 겹침이 화면에 바로 보인다 |
| 정지 조건을 두지 않는다 | 고정 목표에서만 통하는 기법의 결론을 버리게 되고, 이동 장면 편차의 대조군이 없다 |
| 정지 조건을 사다리 전체에 붙인다 | 조건 수가 두 배가 된다 |
| 계획 문서를 먼저 다 쓰고 시험 실행을 뒤에 한다 | 궤도 속도와 목표 총수를 추측으로 적게 된다 |
| main에서 바로 작업한다 | 새 것이 끝나기 전까지 공개된 결과가 미완성 상태가 된다 |

## 결과

- 승인되면 [ADR-0009](0009-flat-scenario-quality-by-distance.md)는 "대체됨"이 된다. "ADR 이전의 결정" 표의 "오브"(고정 중심 목표)와 "AI 범위"(직진 스티어링)는 `v2`에서 유효하지 않다.
- 거리 구간과 표현 선택([ADR-0010](0010-final-representation-bands.md), [ADR-0011](0011-entity-driven-crowd-particles.md))은 계획 문서에서 다시 본다.
- `v1`의 수치와 `v2`의 수치는 잇지 않는다.
- 실행에서 확인한 것은 시험 실행부터 덧붙인다.
