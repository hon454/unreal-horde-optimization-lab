# ADR-0011 200m 밖 배경 무리의 입자를 실제 엔티티 자리에 그린다

- 상태: 승인됨(2026-11-12 채팅에서 사용자가 승인)
- 날짜: 2026-11-12

그리는 끝(카메라 200m) 밖의 Niagara 배경 무리를 두 겹으로 만든다. 200\~500m는 그려지지 않는 실제 Mass 엔티티의 위치를 매 프레임 Niagara에 배열로 넘겨 그 자리에 입자를 그린다. 엔티티가 없는 500\~1,000m는 중앙으로 직진하는 독립 입자다. 독립 입자만 쓰던 첫 구현은 입자와 미니언이 대응하지 않아 경계에서 개체가 사라지고 다른 자리에 생기는 것이 눈에 띄었다. 대신 CPU에서 위치를 모으는 비용이 매 프레임 들고, 그 크기는 `Full1`에서 처음 잰다.

## 맥락

[ADR-0009](0009-flat-scenario-quality-by-distance.md)는 그리는 끝 밖을 Niagara 배경 무리로 채우기로 했다. Q2의 첫 구현은 오브 둘레 고리에 독립 GPU 입자를 뿌렸고(자율 결정 D1\~D4, D6), 사용자가 움직이는 화면을 보고 경계가 눈에 띈다고 했다(D17).

| 사실 | 근거 |
| --- | --- |
| 실제 미니언은 카메라 188m에서 나타나고(Off→Low 히스테리시스) 독립 입자는 오브 기준 반경에서 사라진다. 기준점이 달라 자리가 대응하지 않는다 | `MassLODCalculator.h:864-886`, [Worklog/Q2.md](../Worklog/Q2.md) |
| 200m 밖 엔티티는 3m/s 직선 이동이라 마지막 갱신 위치와 시각에서 외삽한 값이 정확하다 | `ULabOffMoveProcessor`(`Source/HordeOptLab/LabMassProcessors.cpp`) |
| 배열 데이터 인터페이스는 GPU 이미터에서 읽을 수 있다 | `NiagaraDataInterfaceArray.h`, [engine-notes.md](../Reference/engine-notes.md) 24절 |
| 엔티티는 맵 반경 500m 안에만 있다. 바깥 반경 1,000m는 사용자 확정값이다 | [measurement.md](../Guides/measurement.md) "확정값" |
| 독립 입자 16,544개는 1만 P1에서 GPU p50 +3.9ms, 프레임 p50 +0.87ms였다 | 마일스톤 묶음 Q4, 자율 결정 D14 |

## 결정

1. 200\~500m는 엔티티 구동 입자다. 그려지지 않는(표현 LOD Off) 엔티티의 위치를 매 프레임 모아 Niagara에 넘긴다.
2. 500\~1,000m는 독립 입자다. 수는 호드 총수 N에 비례하게 둔다(경계를 지나는 흐름을 실제 미니언과 맞춘다).
3. 경계에 페이드를 넣지 않는다. 입자와 미니언이 같은 개체라 대응이 맞는다.
4. 입자의 그림자는 원거리 그림자 스위치(`-LabFarShadow`)를 따른다. 최종 구성에서는 끔이다([ADR-0010](0010-final-representation-bands.md)).
5. `-LabCrowdFx`의 기본값은 0이고 사다리 7·8단계의 변형이 켠다. 단계 1\~6의 동작은 바뀌지 않는다([ADR-0004](0004-stages-as-run-modes.md)).
6. Niagara의 값은 `L8`과 빼 보기 `A8-farcull`(200m 밖 엔티티를 입자 대신 ISKM으로 그린다), `A8-crowdfx`(배경 무리 끔)로 `Full1`에서 잰다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 독립 입자만(Q2 첫 구현). 안쪽 반경을 200m에서 172.8m로 옮겨 빈 띠를 줄였다 | 입자와 미니언이 대응하지 않아 경계에서 개체가 사라지고 다른 자리에 생긴다. 반경 식이 P1 카메라의 오프셋에 맞춘 것이라 다른 방향에서는 어긋난다 |
| 겹쳐서 디더 페이드 | 개체가 대응하지 않아 어른거림이 남고 새 머티리얼과 셰이더 비용이 든다 |
| 톤만 맞추기 | 위치 불일치가 남는다 |
| 500m 밖 비우기 | 사용자 확정값 1,000m와 어긋나고 수평선이 빈다 |
| 위치를 1Hz로 모으기 | 카메라가 물러날 때 최대 한 주기 동안 겹치거나 빈다 |
| 고정 입자 수 | 보조 묶음(5k, 2만, 3만)에서 배경만 같은 밀도로 남아 경계가 눈에 띈다 |
| 입자 그림자를 원거리 스위치와 따로 두기 | 조건이 2×2로 늘고 표에 설명이 더 필요하다(자율 결정 D19) |

## 결과

- `q2crowd`·`q4final`의 뜻이 바뀌어 Q2\~Q4 묶음의 배경 무리 수치는 `Full1`과 견주지 않는다.
- 만드는 순서는 `Scripts/create-crowd-fx.md`, 구현 경위는 [Worklog/Q2.md](../Worklog/Q2.md) "Q2b"·"Q2c"에 있다.
- Niagara가 ISKM보다 싼지는 근거가 없다. 예행 `Reh2`(1만 P1, 10초 1회)의 프레임 p50은 `L8` 11.14ms, `A8-farcull` 11.79ms, `A8-crowdfx` 7.40ms였고, 한 번씩이라 판단에 쓰지 않는다.
- 실행에서 확인한 것은 `Full1` 뒤에 덧붙인다.

### `Full1` 실행 결과(2026-11-12)

Test 패키지 730ff18, 세 회차 중앙값, 출처는 `Measurements/Full1/summary.csv`다. 별말이 없으면 1만 P1이다.

| 조건 | 프레임 p50 | 프레임 p95 | Game p50 | GPU p50 | 병목 |
| --- | --- | --- | --- | --- | --- |
| `L6-m5bounds`(배경 무리 없음) | 7.38 | 8.84 | 7.20 | 5.28 | Game |
| `L7-q2crowd`(엔티티 구동 입자) | 12.51 | 13.03 | 7.88 | 12.11 | GPU |
| `L8-q4final` | 11.12 | 11.64 | 7.82 | 10.71 | GPU |
| `A8-crowdfx`(L8에서 배경 무리 끔) | 7.46 | 8.90 | 7.32 | 5.19 | Game |
| `A8-farcull`(L8에서 200m 밖을 입자 대신 ISKM으로) | 11.82 | 13.29 | 11.60 | 7.70 | Game |

- 배경 무리의 값: `L8`에서 끄면(`A8-crowdfx`) 프레임 p50 −3.66ms, GPU p50 −5.53ms이고 Game p50은 −0.49ms다. 입자의 비용은 거의 GPU에 실린다. `L6`에서 `L7`로 갈 때도 같다(GPU p50 +6.83ms, Game p50 +0.68ms).
- 트레이스(사다리 7단계, 병렬 한 회)에서 입자의 GPU 비용은 `BasePass` 0.25 → 2.73ms, `RenderVelocities` 0.19 → 2.98ms, `LumenSceneLighting` 0.48 → 2.99ms로 든다. 게임 스레드에는 `LabCrowdFxGatherProcessor` 0.16ms만 더한다([Worklog/Q6.md](../Worklog/Q6.md) "Full1 후속 분석").
- 입자를 ISKM으로 바꾸면(`A8-farcull`) 병목이 GPU에서 Game으로 옮겨 간다. `L8` 대비 Game p50 +3.78ms, GPU p50 −3.01ms이고, 프레임 p50 +0.70ms, p95 +1.66ms다. 이 구성(1만 P1, GPU 병목)에서는 입자가 프레임 시간으로 더 싸다. 입자는 GPU에 비용을 싣고, ISKM은 Game에 싣는다.
- 입자 그림자는 원거리 스위치를 따른다(결정 4). `L7`(80m 밖 그림자 켬)에서 `L8`(끔)로 가면 트레이스의 `ShadowDepths`가 2.73 → 0.97ms다(액터 구간 변경과 함께 바뀐 값이라 그림자만의 몫이 아니다. 그림자만의 값은 `A8-farshadow`다).
- 총수가 늘수록 입자 비용이 커진다. `L7`의 프레임 p95는 3만 P1에서 29.42ms로 `L6`의 16.48ms보다 12.94ms 길다(`L6`의 GPU p50 7.46ms, `L7` 27.86ms). N@16.7ms(프레임 p95)는 `L7` 13,808, `L8` 16,826이다.
- 1만 P2(오브 중심, 배경 무리가 화면에 거의 들지 않는 카메라)에서는 `L7` 프레임 p50 5.13ms, `L8` 4.80ms로 `L6`의 5.07ms와 같은 수준이다.
- 예행 `Reh2`의 한 번짜리 값(11.14/11.79/7.40ms)은 `Full1`의 세 회차 값(11.12/11.82/7.46ms)과 같은 방향이다. 판단은 `Full1` 값으로 한다.
