# ADR-0002 측정 인프라를 M0 끝에 동결한다

- 상태: 승인됨(2026-11-08 채팅에서 사용자가 승인)
- 날짜: 2026-11-07

## 맥락

M1\~M5의 수치는 모두 M0 기준선과 비교한다. 비교가 성립하려면 단계마다 바뀌는 것이 최적화 변수 하나뿐이어야 하는데, 시나리오나 측정 절차가 함께 바뀌면 차이가 어디서 왔는지 가를 수 없다. M0을 만드는 동안 이런 변경이 실제로 있었다. Budget Allocator를 켜지 않은 채 잰 `budget` 묶음은 무효가 되었고, 측정 실행에서 저격 이펙트를 끄던 빌드는 2026-11-07 사용자 결정으로 이펙트를 늘 그리게 바뀌어 E0 전체를 다시 잰다.

## 결정

E0을 이펙트를 켠 빌드로 다시 재고 나면 아래를 동결한다. 동결 시점의 커밋에 태그 `M0`을 붙인다.

| 대상 | 동결하는 내용 | 위치 |
| --- | --- | --- |
| 시나리오 | 맵 반경, 이동 속도, 피해 범위와 피해량, 체력, 저격 간격과 수, 저격 최소 거리, 거리 밴드, 시드 | `Source/HordeOptLab/LabConfig.h` `FLabScenario`, [measurement.md](../Guides/measurement.md) "확정값" |
| 스포너 | 정상 상태 분포(밀도 ∝ 1/r), 가장자리 링 재생성, 시드로 재현되는 순서 | `LabCrowdSpawner.cpp` |
| 오브와 이펙트 | 저격 대상 선택(결정적 해시), 범위 피해, 타워·범위·저격 선 이펙트를 측정 실행에서도 그린다 | `LabOrb.cpp`, `/Game/Lab/FX/NS_LabBolt` |
| 카메라 | P1 오브 뒤 회전, P2 탑뷰 100m([ADR-0003](0003-two-camera-presets.md)) | `LabCameraRig.cpp` |
| 벤치마크 러너 | 워밍업 15초, 캡처 60초, 스케일러빌리티 Epic, VSync·프레임 제한·동적 해상도 끔, 2560x1440 창 모드, 첫 조건만 r0을 버린다 | `LabGameMode.cpp`, `Scripts/run-bench.ps1` |
| 기록 형식 | 라벨 `<단계>-<변형>-N<N>-<프리셋><태그>-r<i>`, CSV 메타데이터(`LabAlive`, `LabRespawns`, `LabOk`), `runs.csv`·`summary.csv` 열 | `Scripts/summarize.py` |

동결한 것을 바꿔야 하면 그날 모든 단계를 다시 재고, 바꾼 이유와 날짜를 measurement.md와 해당 Worklog에 적는다. 글의 수치는 그 글이 쓴 태그의 값으로 두고 고치지 않는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 동결하지 않고 필요할 때 고친다 | 단계 사이 차이가 최적화 때문인지 측정 변경 때문인지 가를 수 없다 |
| 마일스톤마다 그 시점 인프라로 잰다 | 최종 비교표에서 단계별 조건이 달라진다. [ADR-0004](0004-stages-as-run-modes.md)로 최신 빌드 하나에서 모든 단계를 잴 수 있으므로 필요 없다 |

## 결과

- 2026-11-08 동결 시점 커밋에 태그 `M0`을 붙였다. 동결 직전에 시나리오가 두 번 바뀌었다(화면 안 구간별 저격, 미니언 Lumen 제외). 둘 다 E0 재측정(태그 `fx`, `fxb`)에 반영되어 있다. 결정 표의 "저격 최소 거리"는 승인 시점에 이미 화면 판정과 거리 구간 배분(`Source/HordeOptLab/LabSnipe.h`)으로 바뀌어 있었고, 동결 대상은 그 규칙이다(표는 승인 당시 문장 그대로 둔다).
