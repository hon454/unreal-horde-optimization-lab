# ADR-0014 글 본문은 표 없이 SVG 그림과 산문으로 쓰고, 수치의 표는 측정 기록에 둔다

- 상태: 승인됨(2026-11-12 채팅에서 사용자가 결정)
- 날짜: 2026-11-12

글 본문(`Posts/NN-이름/README.md`)에는 Markdown 표와 Mermaid를 쓰지 않는다. 수치와 원리는 직접 만든 SVG 그림으로 보이고, 정확한 값의 표는 측정 기록(`measurements.md`)에 둔다. 측정 약어는 풀어 쓰고, 배경 지식은 산문으로 설명한다. 대신 그림 안의 글자는 GitHub에서 검색과 복사가 되지 않고, 다시 재면 그림을 다시 만들어야 한다. 규칙의 문장은 [posting.md](../Guides/posting.md)에 있고, 이 문서는 그 규칙을 정한 이유와 버린 대안을 남긴다.

## 맥락

글 00\~09를 쓰기 전에 시범 글 01(액터 군중 기준선)을 먼저 쓰고 사용자가 GitHub에서 읽었다(2026-11-12). 그 검토와 앞선 글 준비 인터뷰에서 형식이 정해졌다.

| 사실 | 근거 |
| --- | --- |
| 시범 글 01의 표 다섯 개는 모두 요점이 크기 비교나 변화였다. 값을 찾아 읽는 표는 없었다 | `Posts/01-actor-baseline/README.md`(363c6de) |
| "쓰인 것" 표는 칸마다 문장이 들어가 읽기 어려웠고, 한 줄 설명으로는 기술을 설명하기에 짧았다 | 사용자 검토 |
| GitHub는 `N@16.7ms`를 메일 주소로 보고 링크를 건다 | 사용자 검토 |
| "Game p50", "1만 오브 시점" 같은 약어와 줄임말은 독자가 뜻을 알 수 없었다. 게임 스레드만 적으면 다른 스레드의 값을 알 수 없다 | 사용자 검토 |
| GitHub의 Mermaid 도식은 모양을 다듬을 수 없다 | 사용자 검토 |
| GitHub의 Markdown 표는 폭을 지정할 수 없다(내용 폭만큼만 그려진다) | 이번에 직접 시험하지는 않았다 |
| 글을 모두 쓰면 단계를 고르는 사이트(GitHub Pages)를 만든다 | [backlog.md](../backlog.md) "글 대기열" |

## 결정

1. 글 본문에는 Markdown 표를 쓰지 않는다. 수치는 SVG 그림(막대, 선, 구성 그림)으로 보이고 값을 그림 안에 적는다. 표의 모양을 SVG로 옮겨 그리지 않는다.
2. 그림에 적은 값은 모두 측정 기록의 Markdown 표에 있어야 한다. 수치 그림은 `summary.csv`에서 스크립트로 만든다.
3. 측정 기록과 루트 README는 Markdown 표를 쓴다. 다섯 열까지, 칸 하나에 한 줄까지다.
4. 도식과 차트는 SVG다. Mermaid는 쓰지 않는다.
5. 핵심 발견에는 시각 자료가 반드시 하나 있다. Unreal Insights로 분석한 부분은 스크린샷과 함께 보인다.
6. 원리를 코드가 정하는 곳에는 그 코드를 짧게 발췌해 넣는다.
7. 측정 약어와 조건의 줄임말을 본문에 쓰지 않는다. 스레드 시간은 게임 스레드, 렌더 스레드, GPU를 함께 보인다. 촬영과 측정의 사정은 본문에 적지 않는다.
8. 그 글이 처음 다루는 기술은 "배경 지식" 절에서 산문으로 설명한다. 앞 글이 설명한 기술은 다시 설명하지 않는다.
9. "틀렸던 가설" 절은 가설이 측정으로 뒤집힌 글(03, 05, 06)에만 둔다.
10. 경위에는 수치를 쓰지 않는다. 본문의 수치는 최종 측정의 값뿐이다.
11. 문장은 ASD-STE100의 80% 정도를 목표로 하고, 같은 내용이면 글보다 도식, 도식보다 웹 페이지, 웹 페이지보다 영상을 고른다.
12. 글의 형식을 바꾸는 결정은 ADR로 남긴다. posting.md에는 규칙만 적고 결정한 사람과 날짜를 달지 않는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 본문에 Markdown 표를 그대로 쓴다 | 시범 글의 표는 모두 비교가 요점이었다. 숫자를 읽어 견줘야 해서 막대보다 느리고, 폭을 지정할 수 없다 |
| 비교가 요점이면 SVG, 값을 찾아 읽는 표면 Markdown 표 | 글마다 판단이 갈린다. 본문에서 값을 찾아 읽을 일은 측정 기록이 맡을 수 있다 |
| 표를 SVG로 옮겨 그린다(격자에 숫자) | 얻는 것은 폭뿐이고, 검색과 복사가 안 되는 단점은 그대로다 |
| Mermaid 도식과 차트 | 모양을 다듬을 수 없고 사이트로 그대로 옮길 수 없다 |
| "쓰인 것" 표(이름, 한 줄 설명, 이 글에서 한 일) | 칸에 문장이 들어가 읽기 어렵고, 기술을 설명하기에 짧다 |
| 경위의 옛 실험 값을 "참고"로 적는다 | 최종 측정에 대응 조건이 없는 값이 본문의 표와 나란히 읽힌다([ADR-0006](0006-three-measurement-tiers.md)) |
| "틀렸던 가설" 절을 모든 글에 둔다 | 뒤집힌 가설이 없는 글에서는 지어내게 된다 |
| 결정을 posting.md의 규칙 옆에 날짜와 함께 적는다 | 규칙 문서가 길어지고, 버린 대안과 이유를 적을 곳이 없다 |
