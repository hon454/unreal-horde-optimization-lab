# ADR-0015 루트 README도 비교가 요점인 수치는 SVG 그림으로 보이고, 표는 찾아 읽는 목록에만 쓴다

- 상태: 승인됨(2026-11-12 채팅에서 사용자가 결정)
- 날짜: 2026-11-12
- 대체: [ADR-0014](0014-post-format.md)의 결정 3 가운데 루트 README 부분. 측정 기록의 표 규칙과 나머지 결정은 그대로다.

루트 README의 사다리, 빼 보기, 전환 수치는 Markdown 표가 아니라 `summary.csv`에서 스크립트로 만든 SVG 그림으로 보인다. 표는 찾아 읽는 목록(글 목록, 폴더 구조)과 이미지를 나란히 놓는 데만 쓴다. 마일스톤 표는 지운다. 대신 README에서 값을 복사할 수 없으므로 정확한 값은 CSV 링크로 잇는다.

## 맥락

| 사실 | 근거 |
| --- | --- |
| 사다리 표는 여덟 열이라 GitHub에서 칸의 글자가 다음 줄로 넘어갔다. "단계" 열의 `L1`과 "화면" 열의 "보기"는 뜻이 드러나지 않았다 | 사용자 검토(2026-11-12), `README.md`(8b7e046) |
| 사다리, 빼 보기, 전환 표의 요점은 모두 크기 비교나 변화다 | 같은 파일 |
| ADR-0014 결정 3은 "루트 README는 Markdown 표, 다섯 열까지"였고 사다리 표는 이미 이 규칙에 맞지 않았다 | [ADR-0014](0014-post-format.md) "결과" |
| 마일스톤 표의 기법은 사다리와 겹치고, README의 수치는 모두 최종 측정의 값이다 | `README.md` |

## 결정

1. 루트 README에서 크기 비교나 변화가 요점인 수치는 SVG 그림으로 보이고 값을 그림 안에 적는다. 그림은 `summary.csv`(전환은 `transition-dev/runs.csv`)에서 스크립트로 만든다. 그림의 규칙은 글과 같다(posting.md "표와 시각 자료").
2. README의 표는 찾아 읽는 목록과 이미지를 나란히 놓는 데만 쓴다. 세 열까지, 칸 하나에 한 줄까지다.
3. 단계는 "1단계 액터 군중"처럼 번호와 기법 이름으로 부른다. `L1` 같은 조건 라벨은 README에 쓰지 않는다. 단계별 화면은 단계 이름에 건 링크로 잇는다.
4. 마일스톤 표와 마일스톤 묶음의 스크린샷은 README에 두지 않는다. 경위는 Worklog에 있다.
5. 정확한 값은 `Measurements/Full1/summary.csv`와 `Docs/figures/full1/`의 CSV 링크로 잇는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 사다리 표를 다섯 열로 줄여 표로 둔다 | 프레임, 게임 스레드, GPU, 최대 개체 수를 함께 보이려면 열이 모자라고, 숫자를 읽어 견줘야 한다 |
| 전환 표만 표로 남긴다 | 네 행이라 표로도 읽히지만, 요점인 "시드 범위가 겹치는가"는 범위 막대가 바로 보인다 |
| 마일스톤 표를 접어서 남긴다 | 독자에게는 경위이고, `M0`과 "1단계" 두 이름이 섞인다 |
