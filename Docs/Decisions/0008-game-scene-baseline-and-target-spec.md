# ADR-0008 게임 장면을 새 기준선으로 삼고 목표 사양에서 프레임을 맞춘다

- 상태: 제안됨
- 날짜: 2026-11-11

평지에서 최대 개체 수를 좇던 측정을, 실제 게임에 들어가는 호드의 조건을 켠 장면에서 목표 사양을 맞추는 것으로 바꾼다. 장면은 건물과 방향장, 비켜 가기, 시야 검사 저격, 콜리전, 부위 판정, 래그돌을 가진 새 기준선이다. 목표 사양은 호드 총수 1만(잠정)과 60fps이고, 주 지표는 목표 총수에서의 프레임 시간이다. 평지에서 먼저 재서 공개하는 안과 최종 단계에만 게임 조건을 켜는 안은 버렸다. 이렇게 하면 글의 수치가 벤치마크 전용 장면의 값이 아니게 된다. 대신 총괄 묶음 앞에 구현이 여러 건 들어가고, 옛 M0\~M5 묶음의 수치와는 잇지 못한다.

## 맥락

M0\~M5가 끝났고 총괄 묶음의 측정 목록을 정하려던 때다. 사용자는 이 레포가 대규모 호드를 최적화하는 과정과 실제 수치를 보이기를 바랐고, 호드를 벤치마크에서만 쓰는 것으로 전제하지 말라고 했다. 최대 수치를 잡으려고 액터 5천, 1만을 다루는 것보다 목표를 잡고 그 안에서 품질과 프레임을 맞추는 것이 중요하다고도 했다.

| 사실 | 근거 |
| --- | --- |
| 지금 장면은 평지이고 비켜 가기, 액터 캡슐 콜리전, 부위 판정, 래그돌이 없다 | [plan.md](../plan.md) M1 E1 (c), M3b "함께 바꾸는 설정" |
| 액터만으로 60fps를 지키는 최대 N은 813이다(M0 `full`, 평지) | [STATUS.md](../STATUS.md) "측정 결과" |
| 지금 최종 구성은 평지·게임 조건 끔에서 약 17,100이다(2종 P1, 프레임 p95 기준) | 같은 곳, M5 묶음 `m4offpool` |
| 2만 P1에서 캡슐 콜리전은 1.55ms, 가까운 개체만 비켜 가기는 프레임 +10.6ms다. 1만에서는 재지 않았다 | [backlog.md](../backlog.md), [Worklog/M4.md](../Worklog/M4.md) |
| Simulation LOD는 평지에서 프레임 이득이 없었다 | [Worklog/M4.md](../Worklog/M4.md) |
| 시나리오를 바꾸면 새 기준선으로 분리해 이전 단계를 모두 다시 잰다 | AGENTS.md "진행 방식" |

## 결정

1. 총괄 묶음 `Full1`을 게임 장면에서 잰다. 장면 조건(장애물, 방향장, 비켜 가기, 시야 검사 저격)은 전 단계 공통이고, 근거리 조건(콜리전, 부위 판정, 래그돌)은 액터가 있는 단계에만 켠다.
2. 목표 사양은 호드 총수 1만, 60fps다. 1만과 예산 여유분(잠정 20%)은 잠정값이고 품질 올리기 단계와 총괄 묶음에서 재서 확정한다.
3. 주 지표는 목표 총수에서의 프레임 시간이다. 60fps를 지키는 최대 N은 보조 지표로 남긴다.
4. 단계는 여덟이다: 액터 기준선, 로직을 Mass로, ISM + VAT, 근거리 액터 + 애니 예산, Simulation LOD, ISKM, Niagara 배경 무리, 품질 올리기.
5. 오브의 피해 범위를 넓힌다. 0\~30m 발은 실제 트레이스로 쏘고, 근거리 액터 사망은 래그돌이 된다. 무기·전투 시스템은 여전히 만들지 않고 판정과 비용만 다룬다.
6. 글에 넣는 GIF는 러너가 자동 촬영한다.

세부는 [plan.md](../plan.md) "게임 장면 계획"에 있다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 평지에서 총괄 묶음을 먼저 재고 글을 공개한 뒤 장애물 기준선을 세운다(같은 날 앞서 정한 순서) | 글의 수치가 단순화된 장면의 값이 된다. 사용자가 실제 게임 조건을 전제로 하기를 바랐다 |
| 평지 사다리를 재고 최종 단계에서만 게임 조건을 켠다 | "목표 사양을 액터로 돌리면"이라는 출발점이 단순화된 장면의 값이 된다. 구현은 가장 적다 |
| 평지와 게임 장면 양쪽에서 전 단계를 잰다 | 측정과 구현이 가장 많고 글의 표가 두 벌이 된다 |
| 목표 총수를 2만이나 5천으로 고정한다 | 2만은 게임 조건을 켜면 60fps를 못 지킬 가능성이 높고, 5천은 Mass 쪽 단계의 차이가 작게 나온다. 어느 쪽도 재지 않았으므로 1만을 잠정으로 두고 재서 정한다 |
| 주 지표를 최대 N으로 유지한다 | 목표 없이 수치만 키우게 된다. 품질과 프레임을 맞바꾸는 판단이 드러나지 않는다 |

## 결과

- 이 ADR이 승인되면 [ADR-0002](0002-freeze-measurement-infra.md)가 동결한 시나리오(평지, 저격 구간, 피해 규칙)는 옛 기준선의 것이 된다. 새 기준선의 측정 인프라는 G7에서 다시 동결한다.
- "ADR 이전의 결정" 표의 "AI 범위"(경로 탐색 없음, 직진 스티어링)와 "오브"(피해는 체력 차감과 태그까지)가 이 결정과 다르다. 승인 뒤 표에 대체 표시를 한다.
- AGENTS.md의 비목표와 시나리오 고정 문장, 화면 녹화 규칙을 이 결정에 맞게 고쳐야 한다. 사용자 확인 뒤에 고친다.
- 실행에서 확인한 것은 G1부터 덧붙인다.
