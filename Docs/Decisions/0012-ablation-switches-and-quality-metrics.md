# ADR-0012 빼 보기는 끄는 인자 하나로 고르고, 전환 점수는 Development에서 낸다

- 상태: 승인됨(2026-11-12 채팅에서 사용자가 승인)
- 날짜: 2026-11-12

빼 보기 표의 행은 "최종 변형 + 끄는 인자 하나"로 고르고, 새 인자는 0일 때만 듣는다. 품질 지표 가운데 전환 점수와 빠른 회전 뒤 채워지는 시간은 Development 빌드에서 참고값으로 내고, Test 묶음의 품질 열은 화면 안 액터 수와 30m 안 액터 비율로 한다. 프레임 수치를 Test 패키지에서만 잰다는 [ADR-0001](0001-test-package-for-measurement.md)은 그대로다. 대신 품질 지표 둘은 빌드 구성이 다른 묶음에서 나오므로 표에 그 사실을 적어야 한다.

## 맥락

[ADR-0009](0009-flat-scenario-quality-by-distance.md) 결정 5는 최종 구성에서 기법 하나만 뺀 실행을 재고, 이점을 프레임 시간, 같은 프레임에서의 품질(액터 수, 전환 점수), 화면 중 하나로 인정한다. 그 구현을 Q3·Q4에서 코디네이터가 정했다(자율 결정 D9, D10, D13).

| 사실 | 근거 |
| --- | --- |
| `run-bench.ps1`은 새 변형 이름을 받지 않고 고치지 않는 파일이다 | 사용자 지시, 자율 결정 D8 |
| 전환 점수는 전환 이벤트 로그와 연속 캡처에 기대고 Test 구성에는 그 로그가 없다 | [Worklog/Q3.md](../Worklog/Q3.md) |
| 같은 시드의 Development 네 실행은 장면이 같았다(`kills=1207`) | [Worklog/Q3.md](../Worklog/Q3.md) |
| P1 카메라는 1rpm으로만 돈다. 빠른 회전은 개발용 인자다. 카메라 프리셋은 동결한 측정 인프라다 | [ADR-0002](0002-freeze-measurement-infra.md), [Worklog/Q4.md](../Worklog/Q4.md) |

## 결정

1. 빼 보기 행은 최종 변형 위에 인자 하나다: `-LabHydrate=0`, `-LabScreenSigBudget=0`, `-LabHydrateFixMask=0`, `-LabEntityPool=0`, `-LabSimLod=0`, `-LabIskm=0`, `-LabFixedBounds=0`, `-LabFarCull=0`, `-LabCrowdFx=0`, `-LabFarShadow=1`(이 행만 다시 켜는 방향이다).
2. 새 스위치는 기법을 빼는 방향으로만 듣는다. 기법이 없는 단계에서 켜지는 조합을 만들지 않는다.
3. 실행마다 CSV 메타데이터 `LabTech*`와 적용값을 남기고 러너가 기대값과 대조한다(`Scripts/ablation-check.py`, `Scripts/full-conditions.json`).
4. 전환 점수(ISKM 대 VAT, 전환 대책 켬 대 끔)는 총괄 묶음과 같은 커밋의 Development 실행 묶음에서 낸다. 네 조건 × 시드 3개다. 표에 "Development, 화면 캡처 기반"이라고 적는다.
5. Test 묶음의 품질 열은 화면 안 액터 수와 "카메라 30m 안 화면 안 개체 중 액터의 비율"이다. 빠른 회전 뒤 채워지는 시간은 Development 참고값으로만 적는다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| `-LabAblate=<행>` 인자 하나 | 기존 인자와 뜻이 갈려 같은 설정을 두 곳에서 고르게 된다 |
| 새 인자를 0/1 양방향으로 | 확인하지 않은 조합이 열린다 |
| "200m 밖 지우기 끔" 행에서 배경 무리도 끄기 | 한 행에서 변수가 둘 바뀐다 |
| Test 빌드에 전환 이벤트 로그 넣기 | 측정 빌드에 로그 경로가 생겨 다른 수치에 영향을 줄 수 있다 |
| Test 카메라 프리셋에 빠른 회전 구간 넣기 | 동결한 카메라 프리셋이 바뀌어 전 단계를 다시 재야 한다 |

## 결과

- Development 참고(1만 P1, 1회)로는 엔티티 풀, 전환 대책, 배경 무리, 하이드레이션 행이 프레임 이점을 보이지 않았다. 이 넷의 이점은 전환 점수, 화면, 스파이크로 보여야 한다([Worklog/Q3.md](../Worklog/Q3.md)).
- 전환 점수는 자세가 이어지는지를 직접 재지 않는다(이웃 개체, 카메라 회전, 모션 블러가 섞인다). 잡음은 시드 3개로 본다.
- 실행에서 확인한 것은 `Full1`과 Development 전환 점수 묶음 뒤에 덧붙인다.

### `Full1` 실행 결과(2026-11-12)

Test 패키지 730ff18, 1만 P1, 세 회차 중앙값, ms. 출처는 `Measurements/Full1/summary.csv`다. 기준 `L8-q4final`은 프레임 p50 11.12, p95 11.64, Game p50 7.82, GPU p50 10.71이다. 차이는 기준에서 뺀 값이다.

| `A8-hydrate`(`-LabHydrate=0`) | 11.08 | 11.54 | 3.74 | 10.74 | −0.04 | −4.07 |

| `A8-pool`(`-LabEntityPool=0`) | 11.14 | 11.65 | 7.81 | 10.72 | +0.02 | −0.01 |
| `A8-simlod`(`-LabSimLod=0`) | 11.15 | 11.71 | 8.45 | 10.73 | +0.03 | +0.64 |
| `A8-iskm`(`-LabIskm=0`) | 12.40 | 12.83 | 7.80 | 12.00 | +1.28 | −0.02 |

- 빼면 프레임 시간이 달라지는 행은 `A8-iskm`(+1.28ms), `A8-farshadow`(+1.40ms), `A8-farcull`(+0.70ms)이고, 앞 둘은 GPU에서 난다. `A8-crowdfx`(−3.66ms)는 기법을 빼는 행이 아니라 입자 비용을 보이는 행이다.
- 프레임 시간이 같은 행 다섯(`A8-hydrate`, `A8-budget`, `A8-fix`, `A8-pool`, `A8-bounds`)은 최종 구성의 병목이 GPU라서 Game 부하가 프레임에 드러나지 않는다. Game p50은 `A8-hydrate` −4.07ms, `A8-budget` +0.82ms, `A8-simlod` +0.64ms로 갈린다. 이 셋의 이점은 Game 열로 읽는다. `A8-fix`와 `A8-pool`은 프레임·Game 어느 쪽에서도 갈리지 않는다(이 둘의 이점은 전환 점수·화면·스파이크에서 찾아야 한다).
- 병목은 행마다 다르다. `A8-farcull`만 Game이다(Game p50 11.60 대 GPU p50 7.70). `A8-crowdfx`도 Game이지만(7.32 대 5.19) 두 값 모두 L6 수준으로 내려간 것이다. 나머지 여덟 행은 GPU다.
- 품질 열(결정 5): 액터 수 평균은 457 안팎(화면 안 364 안팎)으로 `A8-hydrate`를 뺀 모든 행이 같다. 30m 안 액터 비율도 0.98\~0.99로 같다. `A8-hydrate`는 액터가 없어 두 열이 비어 있다.
- 전환 점수와 빠른 회전 뒤 채워지는 시간(결정 4, 5의 Development 참고값)은 이 `Full1`에 들어 있지 않다. 별도 묶음에서 낸다.

### Development 전환 점수 묶음 결과(2026-11-12)

Development 에디터 `-game`, 소스는 `Full1`과 같은 730ff18, `q4final` 1만 P1, 화면 캡처 기반(hydrate 사건의 튐 평균, 시드 셋의 중앙값). 출처는 `Measurements/Full1/transition-dev/runs.csv`, 경위는 [Worklog/Q6.md](../Worklog/Q6.md) "Development 전환 점수 묶음".

| 조건 | 튐 평균 | 시드 셋 |
| --- | --- | --- |
| ISKM, 대책 전부(최종 구성) | 4.63 | 4.59\~4.82 |
| VAT, 대책 전부 | 5.22 | 4.71\~5.25 |
| ISKM, 대책 끔 | 7.46 | 7.13\~7.64 |

- 전환 대책을 끄면 튐 평균이 2.3\~2.8 오르고 눈에 띈 전환이 3\~5%에서 9\~11%로 는다. 세 시드 모두 같은 방향이다. `A8-fix` 행의 이점은 이 값으로 적는다.
- ISKM과 VAT의 차이는 대책을 켠 채로 0.12\~0.62이고 대책을 끄면 순서가 시드마다 다르다. ISKM의 이점은 전환 점수가 아니라 프레임으로 적는다.
