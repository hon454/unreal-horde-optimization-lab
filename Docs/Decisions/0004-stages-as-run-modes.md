# ADR-0004 최적화 단계를 한 빌드 안의 실행 모드로 공존시킨다

- 상태: 승인됨(2026-11-07 채팅에서 사용자가 결정)
- 날짜: 2026-11-07

## 맥락

계획은 마일스톤마다 태그를 붙이고, 재측정이 필요하면(측정 인프라 변경, M3b 새 기준선, 최종 비교표) 태그를 하나씩 체크아웃해 패키지를 새로 빌드해 재는 방식이었다. Test 패키지 첫 빌드는 26분, 이후는 몇 분씩 걸리고, 태그마다 빌드하면 그 사이 엔진 설정이나 러너가 조금씩 달라질 여지가 있다. 사용자는 최신 코드에서 이전 단계를 바로 재고 비교하기를 원했다.

## 결정

- 각 마일스톤의 구현을 지우지 않고 새 단계로 더한다. 실행 인자 `-LabStage=M0|M1|...`가 단계를 고르고, M0 안의 변형은 `-LabVariant=`로 남는다(`Source/HordeOptLab/LabConfig.h` `ELabStage`).
- 스포너, 오브, 카메라 프리셋, 벤치마크 러너, CSV 형식은 모든 단계가 공유한다. 단계는 개체를 표현하고 움직이는 방식만 바꾼다.
- 아직 없는 단계를 고르면 게임이 종료 코드 2로 끝난다.
- 태그 `M<N>`은 계속 붙인다. 글의 수치는 태그 시점의 측정값이고, 재측정과 최종 비교표는 최신 빌드 하나에서 단계를 바꿔 가며 잰다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| 태그 체크아웃 후 태그별 패키지(기존 계획) | 재측정마다 태그 수만큼 빌드가 필요하고, 태그 사이에 공용 코드·설정이 달라져 비교가 덜 공정하다 |
| 단계마다 별도 맵·게임 모드 | 공유해야 할 시나리오 코드가 갈라진다 |

## 결과

- 공용 코드를 고치면 이전 단계도 작은 실행으로 확인해야 한다(완료 확인에 단계별 `run-dev.ps1 -Small` 추가).
- 최신 빌드로 다시 잰 이전 단계 수치는 태그 당시 수치와 다를 수 있다. 차이는 그대로 기록한다.
