# ADR-0020 맵 밖 무리를 기록으로 굴리고, 죽은 개체는 맨 앞 기록의 자리에서 다시 생긴다

- 상태: 승인됨(2026-11-15 채팅에서 사용자가 승인. 작업 세션 `m6-vanish` 초안. [ADR-0011](0011-entity-driven-crowd-particles.md) 결정 2를 대체한다)
- 날짜: 2026-11-15

맵 중심 500m 고리에서 대형 미니언이 한 프레임에 사라지고 다른 자리에서 한 프레임에 나타난다. 맵 밖(500\~1,000m) 독립 입자는 500m에서 수명이 끝나 사라지고, 죽은 개체는 같은 고리의 무작위 자리에서 다시 생기기 때문이다. 수는 맞지만 자리가 대응하지 않는다. 맵 밖 무리를 코드가 기록으로 굴리고, 개체가 죽으면 같은 종류에서 오브에 가장 가까운 기록을 그 자리에서 엔티티로 바꾼다. 입자가 끝나는 자리와 개체가 생기는 자리가 같아져 이음매가 사라진다.

## 결정

1. 맵 밖 무리는 코드가 굴리는 기록 N개다. 기록 하나는 (자리, 마지막 이동 시각, 일련번호)이고 걷기 위상과 종류는 일련번호의 결정적 값이다. 처음에는 맵 중심 500\~1,000m에 밀도 1/r로 둔다. 1초 간격으로 오브의 지금 위치를 향해 3m/s로 옮긴다.
2. 개체가 죽으면 같은 종류의 기록 가운데 오브에 가장 가까운 것을 꺼내 그 자리에서 엔티티를 만든다. 꺼낸 수만큼 1,000m 고리의 무작위 각도에 새 기록을 더한다. 엔티티 N과 기록 N은 늘 그대로다.
3. 단계 7·8은 기록을 엔티티 구동 입자 배열의 뒤에 붙여 그린다. 독립 이미터는 스폰율 0으로 끈다.
4. 단계 1\~6도 같은 기록과 같은 재생성 규칙을 쓴다. 그리지 않을 뿐 장면은 같다([ADR-0017](0017-roaming-orb-and-equal-function-ladder.md)).
5. 끄는 스위치는 `-LabFarHandoff=0`(지금 동작), 메타데이터는 `LabFarHandoff`다.
6. 이 결정은 시나리오 고정값(재생성 링)과 동결된 측정 인프라(스포너, [ADR-0002](0002-freeze-measurement-infra.md))를 바꾼다. `Full4` 전에 넣고 `Full4`에서 처음 잰다.

## 고려한 대안

| 대안 | 버린 이유 |
| --- | --- |
| A. 시간 기준 크기 페이드(독립 입자는 끝 2초에 줄이고 재생성 개체는 처음 2초에 키운다) | 다른 두 개체가 다른 자리에서 사라지고 생기는 구조가 남는다. 튐을 흐리게 할 뿐이다. 현업에서 페이드는 같은 개체의 표현 전환에 쓰고, 생성·제거는 시야 밖에서 하거나 한 무리로 잇는다 |
| B. 거리 기준 크기 페이드(에셋만 고친다) | A의 문제에 더해 재생성 자리가 490\~500m 무작위라 나타날 때 크기가 0\~0.5에서 시작해 작은 튐이 남는다 |
| C. 독립 입자를 그대로 두고 그 입자가 끝나는 자리를 코드가 다시 계산해 재생성한다 | Niagara의 난수와 GPU 계산을 CPU에서 똑같이 재현해야 한다. 엔진이 바뀌면 깨진다 |
| D. 이음매를 시야 밖으로 옮긴다 | P1 시야에 500m가 늘 보인다. 맵 반경은 사용자 확정값이다 |
| E. 기록을 맵 중심으로 걷게 한다(지금 독립 입자와 같게) | 엔티티는 오브를 향해 걷는다. 기록이 엔티티가 되는 순간 방향이 바뀐다 |

## 결과

- 좋아지는 것: 500m 경계에서 개체가 사라지고 생기는 것이 없어진다. 맵 밖 무리도 오브를 향해 걸어 엔티티 쪽과 흐름이 이어진다.
- 나빠지는 것: 기록 N개를 1초 간격으로 옮기고 단계 7·8에서 매 프레임 배열에 붙이는 CPU 비용이 는다. 크기는 묶음에서 잰다. 엔티티 구동 이미터의 미리 할당 수를 늘려야 한다(에디터 작업).
- 바뀌는 것: 재생성 자리가 무작위 고리가 아니라 맨 앞 기록의 자리다. 사망과 유입이 다르면 엔티티가 500m 밖이나 안에서 생길 수 있다. 맨 앞 기록의 거리를 로그로 본다.
