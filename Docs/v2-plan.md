# v2 계획 문서

- 상태: 잠정 확정(2026-11-15). 사용자가 자리를 비운 동안 코디네이터가 추천안으로 정했다. 사용자 검토를 기다린다.
- 무엇을 만드는지는 [v2-spec.md](v2-spec.md)에 있다. 결정의 근거와 대안은 [autonomous-decisions.md](Worklog/autonomous-decisions.md)의 D33부터에 있다.
- 경위는 [Worklog/V2.md](Worklog/V2.md)에 쌓는다. 작업 단위마다 절 하나다.

## 진행 방식

- 작업 단위 하나에 새 작업 세션 하나다. 세션은 끝나면 보관한다. 다음 세션은 Worklog를 근거로 넘겨받는다.
- 빌드, 패키징, 측정은 한 번에 한 세션만 한다. 그래서 코드 작업 단위는 차례로 돈다.
- 상세 계획안: 세션은 조사 단계 뒤에 자기 Worklog 절에 상세 계획안(바꿀 파일, 순서, 확인 방법, 갈리는 선택과 추천)을 적는다. 사용자가 자리에 있으면 승인을 받는다. 자리에 없으면 추천안으로 진행하고 대안과 득실을 Worklog에 남긴다(D33).
- 각 작업 단위의 완료 조건은 [AGENTS.md](../AGENTS.md) "완료 확인"이다. 수치 판단은 Test 패키지의 작은 묶음으로 한다(조건마다 3회).
- 사다리의 단계 목록은 아래 표가 출발점이다. W3과 W5의 트레이스 결과로 고칠 수 있다. 고치면 이 문서와 결정 기록에 적는다.

## 사다리(출발점)

모든 단계가 [v2-spec.md](v2-spec.md) 3절의 기능 넷을 한다.

| # | 단계 | 내용 | 성격 |
| --- | --- | --- | --- |
| 1 | 액터 기준선 | 캡슐과 이동 컴포넌트가 있는 액터. 겹침 방지는 액터마다 이웃을 찾아 조향 | 출발점 |
| 2 | Mass, 엔진 기본 경로 | 엔진의 이동·회피·표현 프로세서를 그대로. 가까운 개체는 엔진 하이드레이션 액터, 나머지는 ISM | 버는 단계 |
| 3 | 직접 짠 로직 | 트레이스가 가리킨 병목(겹침 방지, 액터 동기화)을 Lab 프로세서로 바꾼다 | 버는 단계 |
| 4 | 애니메이션 표현 | ISM + VAT, 액터에 애니 예산 | 품질 |
| 5 | Simulation LOD + 엔티티 풀 | 먼 개체의 로직을 드물게, 200m 밖 자체 이동 | 버는 단계 |
| 6 | ISKM | 먼 표현을 ISKM으로, 따라가는 바운드 | 품질 |
| 7 | 배경 무리 | 엔티티 구동 입자와 독립 입자 | 품질 |
| 8 | 품질 올리기 | 액터 상한, 전환 거리, 그림자 | 번 것을 쓰는 단계 |

빼 보기 표는 단계 8에서 기법 하나씩을 끈 실행이다. 정지 조건은 단계 8과 빼 보기에만 붙인다.

## 작업 단위

차례는 의존 순이다. 괄호는 기본 모델이다.

| # | 작업 단위 | 내용 | 끝났다는 것 |
| --- | --- | --- | --- |
| W1 | 시나리오 뼈대(Opus) | 시험 실행 코드를 본 구현으로 올린다: 궤도와 구간을 `FLabScenario` 상수로, 따라가는 카메라를 기본으로, 오브·카메라 HUD(화살표 없음), CSV 메타데이터, 러너의 워밍업·구간 인자. 저격 해시 수정과 분포 확인 | 기본 인자의 작은 실행이 이동 시나리오로 돈다. 저격 대상이 틱마다 다르다 |
| W2 | 서브시스템 접근 선언(Opus) | Lab 프로세서의 `GetSubsystem`·`FScopeLock`을 `AddSubsystemRequirement`와 실행 컨텍스트로 바꾼다. 동작은 그대로 | 전 단계 작은 실행 통과. 개체 수와 초당 사망이 바꾸기 전과 같다 |
| W3 | 겹침 방지, 엔진 경로(Opus) | 엔진 회피 프로세서를 Mass 단계에 켠다. 겹친 쌍의 수 지표를 더한다. 트레이스로 비용이 어느 프로세서에 있는지 확정한다([Worklog/M4.md](Worklog/M4.md)의 미확인 +10.6ms) | 겹친 쌍의 수가 CSV에 남는다. 비용의 출처가 프로세서 이름으로 적힌다 |
| W4 | 겹침 방지, 직접 구현(Opus) | W3의 트레이스가 가리키면 격자 기반 분리 조향을 Lab 프로세서로 짠다. 같은 겹침 수준에서 비용을 견준다 | 엔진 경로와 같은 겹침 수준, 더 낮은 Game 시간. 아니면 "엔진 경로로 충분"을 적고 닫는다 |
| W5 | 캡슐과 액터 비용(Opus) | 하이드레이션 액터에 캡슐을 기본으로 켠다. 저격의 캡슐 트레이스. 액터 개당 Game 비용을 트레이스로 나누고 줄인다 | 캡슐 트레이스 수가 CSV에 남는다. 액터 개당 비용의 분해가 Worklog에 있다 |
| W6 | 액터 기준선(Opus) | 단계 1을 같은 기능으로 다시 만든다: 캡슐, 이동, 액터마다의 겹침 방지 | 단계 1이 기능 넷을 한다. 500\~2,000에서 작은 실행 |
| W7 | 전환(Opus) | 최소 유지 시간, 상한에서의 가까운 순 배정, 왕복 수 목표. 방향별 지표 정리 | 이동 시나리오의 왕복 수가 목표 안. 근거 묶음 |
| W8 | 움직이는 오브용 기법(Opus) | 200m 밖 이동, 입자 외삽, 독립 입자 고리, 따라가는 바운드. 전환 증상의 영상 재현과 확인 | 영상 비교에서 증상이 없다. 원인이 Worklog에 확정돼 있다 |
| W9 | ISKM 번쩍임(Opus) | 엔진의 이전 프레임 변환 경로를 추적해 원인을 확정하고 막는다 | 같은 장면의 영상에서 번쩍임이 없다. 원인이 소스 위치로 적힌다 |
| W10 | 사다리 배선과 삭제(Opus) | 단계 2(엔진 표현 경로)와 단계 3\~8을 `-LabStage=`로 맞춘다. 사다리에 없는 변형과 고정 목표 전용 코드를 지운다 | 여덟 단계와 빼 보기가 인자로 돈다. `code-tour.md` 갱신 |
| W11 | 품질 올리기(Opus) | 목표 사양 안에서 액터 상한과 전환 거리를 재서 정한다. ADR 초안 | 최종 구성의 값과 근거 묶음, ADR 초안 |
| W12 | 측정 준비(Sonnet) | 조건 표, 러너, 동등성 검사(겹친 쌍 포함), 요약·그림 스크립트. 측정 인프라 동결 | 마른 실행 통과. `measurement.md` 갱신 |
| W13 | 총괄 묶음 `Full4`(Sonnet) | 전 조건 측정 | `Measurements/Full4/` |
| W14 | 공개 자료 | 글, README, 사이트 교체. 사용자 검토 뒤 main 병합 | 사용자 승인 |

- W3과 W5가 가장 불확실하다. 엔진 회피의 비용이 목표 사양을 넘기면 W4와 W11에서 푼다. 그래도 넘으면 목표 총수를 다시 정하는 ADR 초안을 쓰고 사용자에게 알린다.
- W8과 W9는 서로 독립이지만 빌드가 하나라 차례로 돈다.
- W13 이후는 사용자가 사양 문서와 결과를 검토한 뒤에 시작한다. 긴 측정과 공개 자료는 방향이 틀렸을 때 버리는 것이 크다.

## 조건 표(출발점)

측정 한 번이 240초다(워밍업 60초 + 측정 180초). `v1`의 75초보다 길어 조건 수를 줄인다. 값은 W12에서 확정한다.

| 묶음 | 조건 | 실행 수 |
| --- | --- | --- |
| 사다리 | 8단계 × 1만 × 따라가는 카메라 × 3회 | 24 |
| 빼 보기 | 10행 안팎 × 1만 × 3회 | 30 |
| 정지 조건 | 단계 8과 빼 보기 × 3회 | 33 |
| 보조(최대 N) | Mass 단계 × {5천, 2만} × 3회 | 42 |
| 보조(액터) | 단계 1 × {500, 1천, 2천} × 3회 | 9 |
| 트레이스 | 8단계 | 8 |
| 촬영 | 8단계, HUD 켬 | 8 |

약 154회 × 4분 20초 = 약 11시간이다(계산값).

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 엔진 회피 프로세서의 비용이 커서 단계 2가 목표 사양을 크게 넘는다 | 그것이 단계 3의 근거가 된다. 단계 2의 수치는 그대로 보고한다 |
| 겹침 방지가 뭉친 무리에서 떨림을 만든다 | 겹친 쌍의 수와 영상으로 확인한다. 조향 세기와 반경은 W3·W4에서 재서 정한다 |
| ISKM 번쩍임의 원인이 엔진 안이라 Lab에서 못 막는다 | 대체 ADR 초안(모션 벡터 끄기 같은 우회)을 쓰고 사용자에게 묻는다 |
| 이동 시나리오에서 액터가 상한에 붙어 단계 사이의 차이가 안 보인다 | 궤도 속도를 정상 상태가 있는 값으로 골랐다(D34). W11에서 상한을 다시 본다 |
| 측정 시간이 길어진다 | 조건 수를 줄였다. 탑뷰 카메라는 사다리에서 뺐다 |
