# v2 계획 문서

- 상태: 확정(2026-11-15, 사용자 승인). 조건 표는 리뷰([V2-review.md](Worklog/V2-review.md) "사용자 판단")의 수정을 반영한다.
- 무엇을 만드는지는 [v2-spec.md](v2-spec.md)에 있다. 결정의 근거와 대안은 [autonomous-decisions.md](Worklog/autonomous-decisions.md)의 D33부터에 있다.
- 경위는 [Worklog/V2.md](Worklog/V2.md)에 쌓는다. 작업 단위마다 절 하나다.

## 진행 방식

- 작업 단위 하나에 새 작업 세션 하나다. 세션은 끝나면 보관한다. 다음 세션은 Worklog를 근거로 넘겨받는다.
- 빌드, 패키징, 측정은 한 번에 한 세션만 한다. 그래서 코드 작업 단위는 차례로 돈다.
- 상세 계획안: 세션은 조사 단계 뒤에 자기 Worklog 절에 상세 계획안(바꿀 파일, 순서, 확인 방법, 갈리는 선택과 추천)을 적는다. 사용자가 자리에 있으면 승인을 받는다. 자리에 없으면 추천안으로 진행하고 대안과 득실을 Worklog에 남긴다(D33).
- 각 작업 단위의 완료 조건은 [AGENTS.md](../AGENTS.md) "완료 확인"이다. 수치 판단은 Test 패키지의 작은 묶음으로 한다(조건마다 3회).
- 사다리의 단계 목록은 아래 표가 출발점이다. W3과 W5의 트레이스 결과로 고칠 수 있다. 고치면 이 문서와 결정 기록에 적는다.

## 사다리(출발점)

모든 단계가 [v2-spec.md](v2-spec.md) 3절의 기능 넷을 한다.

| # | 단계 | 내용 | 성격 |
| --- | --- | --- | --- |
| 1 | 액터 기준선 | 캡슐과 이동 컴포넌트가 있는 액터. 겹침 방지는 캡슐끼리 막기와 `UCharacterMovementComponent`의 스윕 이동(D47) | 출발점 |
| 2 | Mass, 엔진 기본 경로 | 엔진의 이동·회피·표현 프로세서를 그대로. 가까운 개체는 엔진 하이드레이션 액터, 나머지는 ISM. 200m 밖은 지운다. 액터 동기화는 Lab 프로세서다(D51). 단계 2\~8은 액터 상한 1,000과 전환 거리 35m을 쓴다([ADR-0021](Decisions/0021-unified-actor-cap-and-hydrate-distance.md)) | 비용을 줄이는 단계 |
| 3 | 직접 짠 분리 | 엔진 회피를 Lab 분리 프로세서로 바꾼다(D51). 엔진의 방향 보간 프로세서를 같은 계산의 병렬 사본으로 바꾼다(D61, 사용자 승인 2026-11-16) | 비용을 줄이는 단계 |
| 4 | 애니메이션 표현 | ISM + VAT, 액터에 애니 예산, 전환 규칙([v2-spec.md](v2-spec.md) 4.1절) | 표현을 더하는 단계 |
| 5 | Simulation LOD + 엔티티 풀 | 먼 개체의 로직을 드물게, 200m 밖 자체 이동 | 비용을 줄이는 단계 |
| 6 | ISKM | 먼 표현을 ISKM으로, 따라가는 바운드 | 표현을 더하는 단계 |
| 7 | 배경 무리 | 엔티티 구동 입자와 독립 입자 | 표현을 더하는 단계 |
| 8 | 남은 비용 줄이기 | 80m 밖 인스턴스 그림자 끔, 액터 메시 고정 바운드(D52, ADR-0021). 둘 다 비용을 줄인다. 이름은 사용자가 2026-11-16에 "품질 올리기"에서 바꿨다 | 비용을 줄이는 단계 |

기법별 기여 표는 단계 8에서 기법 하나씩을 끈 실행이다. 정지 조건은 단계 8과 기법별 기여의 조건에만 붙인다.

- W3과 W5가 가장 불확실하다. 엔진 회피의 비용이 목표 사양을 넘기면 W4와 W11에서 푼다. 그래도 넘으면 목표 총수를 다시 정하는 ADR 초안을 쓰고 사용자에게 알린다.

## 조건 표

W12가 정했고 리뷰 반영과 `Full4` 계획 점검이 바꿨다(D53, [Worklog/V2-review.md](Worklog/V2-review.md) "사용자 판단", [Worklog/V2-full4-review.md](Worklog/V2-full4-review.md) "사용자 판단"). 원본은 `Scripts/full-conditions.json`이다. 지금 러너의 실행 하나는 이동 249초, 정지 205초, 트레이스 128초이고, 단계 1의 1만은 365초다(묶음 `V2W12Dry`의 `progress.log` 간격). 러너의 예상 시간 계산도 이 값을 쓴다.

| 묶음 종류 | 조건 | 실행 수 |
| --- | --- | --- |
| 사다리 | 8단계 × 1만 × 이동 × 3회 | 24 |
| 기법별 기여 | 17행 × 1만 × 이동 × 3회 | 51 |
| 정지 조건 | 단계 8과 기법별 기여 15행 × 3회 | 48 |
| 하위 실험 | 단계 8에서 분리 프로세서를 엔진 회피로 바꾼 것 × 3회 | 3 |
| 참고 한 점 | 단계 8 × 탑뷰(P2) × 이동 × 3회. 사다리 표와 그림에 넣지 않는다 | 3 |
| 보조(최대 N) | 단계 2 × {2,500, 5천}, 단계 3\~8 × {1.25만, 2만}, 3회씩 | 42 |
| 보조(액터) | 단계 1과 단계 1 + Animation Budget Allocator(`s1opt`) × {500, 1천, 2천} × 3회 | 18 |
| 같은 조건 다시 재기 | 단계 8 × 3회 | 3 |
| 트레이스 | 8단계 병렬, 단계 2\~8 직렬. 측정 60초 | 15 |

- 207회와 버리는 첫 실행 1회다. 지금 러너의 실행 길이로 13.44시간이고, 재측정 여유 5%를 더하면 14.11시간이다. 상한은 14.62시간이다(러너 `-DryRun`의 계산값).
- 최대 N 보조에서 단계 3\~8의 5천과 단계 2의 2만을 뺐다. 단계 3에 1.25만을 더했다([Worklog/V2-full4-review.md](Worklog/V2-full4-review.md) R4).
- 총수가 1만이 아닌 점의 동등성 실패는 그 점만 기능 미달로 표시하고 최대 N 계산에서 뺀다([measurement.md](Guides/measurement.md) "실패 등급").
- 기법별 기여 17행에는 `a8res`, `a8fxf`, `a8stp`가 든다. 정지 조건에는 `a8fxf`와 `a8stp`를 넣지 않는다(오브와 카메라가 서 있으면 단계 8과 같은 일이다, [measurement.md](Guides/measurement.md) 총괄 묶음 규약).
- 촬영 8회(약 15분)는 따로 돌린다.
- 장치는 가짜 게임, Development 실행, Test 패키지의 작은 묶음 `V2W12Dry`(8회 통과)로 확인했다.

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 엔진 회피 프로세서의 비용이 커서 단계 2가 목표 사양을 크게 넘는다 | 그것이 단계 3의 근거가 된다. 단계 2의 수치는 그대로 보고한다 |
| 겹침 방지가 뭉친 무리에서 떨림을 만든다 | 겹친 쌍의 수와 영상으로 확인한다. 조향 세기와 반경은 W3·W4에서 재서 정한다 |
| ISKM 번쩍임의 원인이 엔진 안이라 Lab에서 못 막는다 | 대체 ADR 초안(모션 벡터 끄기 같은 우회)을 쓰고 사용자에게 묻는다 |
| 이동 시나리오에서 액터가 상한에 붙어 단계 사이의 차이가 안 보인다 | 궤도 속도를 정상 상태가 있는 값으로 골랐다(D34). W11에서 상한을 다시 본다 |
| 측정 시간이 길어진다 | 조건 수를 줄였다. 탑뷰 카메라는 사다리에서 뺐다 |
