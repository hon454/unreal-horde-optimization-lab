# 강연 노트

[references.md](references.md) 영상 1·2(Shabel, 윤준기)의 자동 자막을 분석해 종합한 것이다(2026-11-09, 포크 세션). 타임스탬프는 자막 기준이고 자막 오류로 불확실한 것은 "추정"이다. 자막 원문은 저작물이라 저장소에 두지 않는다. 글에 인용할 때는 타임스탬프와 조건 차이를 함께 적는다.


자료: 자동 자막 `yt/shabel.txt`(Jared Shabel, Unreal Fest Chicago 2026, 영어 43분), `yt/yoon.txt`(윤준기, 언리얼 페스트 서울 2026, 한국어 39분). 서브에이전트 보고 둘을 종합했다. 타임스탬프는 자막 기준. 자막 오류로 불확실한 것은 "추정"으로 표시.

## 2. 강연이 우리 결정에 직접 주는 것

### 코드 정비(결정 3, 확정된 핵심 5)
- **1번 표현 상태 분리**: 두 강연 모두 지지. Shabel 17:46\~20:00(프래그먼트는 멤버 변수, 접근 패턴으로 쪼갠다), 윤준기 19:05(ReadWrite 정리로 병렬 회복). 설계 전에 Shabel 22:59대로 프로세서별 읽기·쓰기 표를 먼저 그린다.
- **추가 후보**: OrbSnipe의 쿼리 밖 쓰기(`GetFragmentDataChecked`)는 Shabel 12:32 "forward declaring all the data access"에 어긋난다(추론). 강연식 해법은 대상에 태그/이벤트 엔티티만 붙이고 쓰기는 MinionState가 맡는 것. 1번 수정 때 같이 처리 가능.
- **추가 후보**: OrbContact를 "피해 이벤트 → 피해 적용 → 체력 0 검사" 셋으로 나누는 구조(Shabel 11:36). E1 (d)에서 "구별되지 않았다"였으므로 M3b에는 넣지 않고 글 02 재료로 둔다.
- **추가 후보(윤준기 16:10)**: 불필요한 엔진 기본 프로세서 끄기. 우리 `DefaultMass.ini`는 켜는 쪽만 있다. 켜져 있는 기본 프로세서 목록을 Mass Debugger로 확인해 끌 것이 있으면 끈다(비용 작음, 묶음 1 기준점에 포함).

### 측정 방법(결정 4)
- **Insights는 필수**: 윤준기 19:13, 37:22\~38:37. "병렬로 돌리면 utrace로도 어떤 프로세서인지 알기 힘들다"는 경고가 있다. 대표 조건(20k P1) 단계별 1개 + `mass.FullyParallel=0` 직렬 1개를 같이 남겨야 프로세서별 시간이 읽힌다.
- **액터 vs Mass 비교 조건**: 윤준기 05:26\~07:06의 45→28ms는 로직 접근 순서만 바꾼 싱글스레드 1만 개 비교다. 우리 "17배"와 직접 비교 금지. 글에서는 "조건이 다르다"를 명시해 인용 가능.
- **Mass Debugger 아키타입 창(청크 채움률)**: 윤준기 33:20. 2종 추가(M3b) 뒤 아키타입이 어떻게 갈리는지 보여 주는 글 이미지로 좋다. 개발 빌드 스크린샷.

### 표현 LOD(결정 5)
- 두 강연 모두 Base/Visible 거리, 히스테리시스, LODMaxCount 수치에 **침묵**. 근거는 앞서 확인한 MetaHuman Crowd·City Sample·엔진 기본값뿐이다.
- 윤준기 23:33의 공식 예시는 고해상 액터 / 저해상 액터 / ISM+VAT 3단. 우리는 저해상 액터 단계를 뺐고 E3 (5)로 근거를 쟀다. 모순 아님.

### 2종 시나리오(결정 8), M4(결정 9)
- Simulation LOD: 두 강연 모두 "있다" 이상 없음. Shabel 38:29는 틱 제한 없이 매 프레임 돌리는 데모를 보였고 07:27에서 틱 제한을 "OOP의 가장 흔한 회피책"이라 불렀다. M4 글에서 "쓰기 패턴 정리가 먼저, 틱 간격은 그 뒤"로 맥락화.
- StateTree + Signal(M4b): 윤준기 21:33\~23:17이 유일한 근거(신호등 예, 걷는 동안 트리는 쉼). Shabel은 StateTree 언급 없음, 태그가 기본형. M4b는 "선택" 유지가 맞다.
- 엔티티 재활용(M5): 둘 다 침묵. Shabel 40:34 "초당 10만 생성·파괴"는 Mass 쪽 생성 비용이 싸다는 뜻. 재활용의 근거는 ISKM 트랙 풀 문제(표현 측)로 서술.

### 하이브리드 구조에 대한 경고
- Shabel 29:38\~31:23: 근접 액터 hydrate 이원 구조는 "개발 시간을 둘로 가른다". 단 30:49에서 **비주얼 파이프라인은 예외**. 우리 액터는 표현 전용(로직은 Mass만)이라 예외에 든다. 액터에 게임플레이 상태를 두기 시작하면 경고 대상. 글 04에 이 경계를 적을 것.
- 윤준기 29:02\~30:56: MassAgentComponent 양방향 동기화는 1프레임 지연. 우리 ActorSync(Mass → 액터 한 방향, 같은 프레임)와의 차이를 글 04에 쓸 수 있다.
