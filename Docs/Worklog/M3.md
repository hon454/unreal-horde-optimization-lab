# M3 작업 기록

초안(2026-11-09). 태그 `M3`를 붙이기 전이다.

## 2026-11-08 설계 결정 (-LabStage=M3)

- 결정은 선택지와 추천을 놓고 하나씩 정했다(사용자). 기준은 "현업에서 실제로 고를 만한 것"이다. (1) 200m 밖은 Off(E2 (c)). 비교 상대는 M2 + Off(`m2off`)이고 같은 묶음에서 다시 잰다. (2) 액터는 M0 캐릭터에서 CharacterMovement 틱만 끈 것, 엔진 풀. (3) AnimBP 시작 시각은 Unreal MCP로 Start Position 핀에 묶었다(`Scripts/bind-anim-start.md`). (4) 저품질 액터 단계는 두지 않고 E3 (5)로 근거를 잰다.
- 동기화는 우리 프로세서 하나(`ULabActorSyncProcessor`, 게임 스레드)가 매 프레임 위치·애니 상태·죽기 진홍을 쓴다. 엔진은 액터를 붙이는 순간에만 위치를 맞춘다.

## 2026-11-08 전환 팝핑과 VAT 그림자

- 팝핑을 고친 순서와 원인은 post-material.md "전환 팝핑은 어디서 생기고 어떻게 줄였나". 처음 기록은 원인을 찾은 순서였다. 사용자 지적으로 2026-11-09에 대책마다 끌 수 있게 하고(`-LabHydrateFixMask`) 문제 크기 순으로 다시 찍었다([Measurements/M3/shots/transition/README.md](../../Measurements/M3/shots/transition/README.md)).
- 죽는 VAT 인스턴스의 칼날 그림자가 바닥에 남았다. Bone VAT 메시의 바운드가 뼈 위치만 덮어 VSM 캐시 무효화가 칼날 끝을 놓쳤다. Vertex 결과의 바운드로 바꿨다(`Scripts/bake-vat.py`, [Measurements/M3/shots/vat-shadow/](../../Measurements/M3/shots/vat-shadow/README.md)).

## 2026-11-09 E3 측정 (M3-mass-*, M3-m2off-*, M3-m3base-*, M3-m3uro-*, M3-m3budget*-*, M3-m3lowres-*)

- `Scripts/run-e3.ps1`. 본 측정은 `mass`·`m2off` × N {1k, 5k, 20k, 50k} × P1·P2 × 3회. 하위 실험은 5k·20k P1이고 같은 묶음 기준점 `m3base`(`mass`와 같은 설정)를 먼저 잰다.
- (1) N@16.7ms(P1): M2 + Off 35,763 → M3 22,046(약 38% 감소). 20k P1 Game Thread 7.08 → 14.41ms, 프레임 10.31 → 15.47ms. P1의 30m 안 액터는 5k 263개, 20k 495개(상한 500).
- 액터가 더한 Game Thread(20k P1, `Scripts/breakdown.py M3-m2off-N20000-P1 M3-mass-N20000-P1`): TickActors +3.5ms, Animation +3.3ms, EndPhysics 대기 +0.5ms.
- (2) URO: 20k Game 14.40 → 13.89, 5k 5.60 → 5.29.
- (3) Budget(`BudgetMs` 2): 20k 거리 단계 12.99, `LODSignificance` 변환 12.91(14.40에서 약 1.4\~1.5ms). 5k는 5.74 / 5.75로 줄지 않는다. 5k의 애니메이션은 1.55ms라 예산 2ms 안이어서 할 일이 없다. 두 중요도 소스는 구별되지 않는다.
- (5) 저품질 액터 단계(15\~30m, URO·최저 LOD·그림자 끔): 5k Game 5.60 → 5.14, 프레임 6.19 → 5.99. 20k Game 14.40 → 13.94, 프레임 15.46 → 15.03. Budget 하나보다 덜 줄인다.
- (4) 풀 크기별 스폰 비용은 하지 않았다.

## 2026-11-09 액터 쪽 비용 순위 (diag-vt*)

- 액터가 있을 때 VAT ISM 프로세서가 1.41 → 3.68ms로 늘었다. 안쪽 반복은 그대로였고(`-LabVatTiming`), 늘어난 2ms는 첫 청크 전, `FMassEntityQuery::ForEachEntityChunk` 안의 `WaitForQueryResources`(`MassProcessingQueueTypes.cpp:678`)였다. 병렬 Mass(`mass.FullyParallel`)에서 게임 스레드가 다른 프로세서가 쥔 자원을 기다린 시간이다. `-dpcvars=mass.FullyParallel=0`이면 액터 유무와 상관없이 1.35ms다. 그 실행의 프레임은 액터 없음 10.52 / 있음 16.28ms(병렬 10.25 / 15.72).
- 직렬 실행에서 액터 495개가 더한 5.76ms: Animation 2.51, ActorSync 1.58, 나머지 TickActors(메시 틱 등) 약 1.7.
- ActorSync 안에서 이동(`SetActorLocationAndRotation`)이 1.22ms다. 캡슐 콜리전 조합(20k P1, 각 3회 중앙값, 프레임): 그대로 15.78, 오버랩·물리 볼륨 갱신 끔 15.64, + QueryOnly 15.49, 콜리전 끔 14.23. 콜리전을 끄면 이동 0.43ms, EndPhysics 대기 0.52 → 0.06ms. 피직스 씬에 바디가 있는 것 자체가 비용이다. 기본값은 바꾸지 않았다(결정 대기).
