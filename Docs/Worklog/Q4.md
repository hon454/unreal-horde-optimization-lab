# Q4 품질 올리기

목표 총수(잠정 1만)·60fps 안에서 액터 상한과 액터로 바뀌는 거리를 올려 최종 구성을 정한다([plan.md](../plan.md) "품질 계획" Q4, 사다리 8단계). 기준점은 `q2crowd`(= `m5bounds` + Niagara 배경 무리, 액터 상한 500, 30m)다. 코디네이터가 사용자 대신 결정하고, 이 단위의 설계 선택도 되돌리기 쉬운 쪽으로 정해 아래에 적는다(2026-11-12).

## 진행

- 조사 끝(2026-11-12): 상한은 `LabCrowdSubsystem.cpp`의 `LODMaxCount[High] = 500`, 전환 거리는 같은 곳의 `VisibleLODDistance[Medium]`(30m, 화면 밖 `BaseLODDistance[Medium]`는 15m)이고 둘 다 인자가 없다(`m3hyd15`·`m3hyd50`은 변형 이름으로만 고른다). P1은 1rpm 회전뿐이고 빠른 회전(`-LabCamTurn`)은 개발 빌드 전용이라 Test 묶음에서 (나)를 잴 수 없다.
- 구현 끝: 인자 `-LabActorCap=`·`-LabHydrateM=`, 변형 `q4final`(값은 묶음 뒤에 넣는다), CSV 스탯 `Lab/ViewActors`·`ViewActors30`·`ViewInst30`·`ViewInstHyd`, 메타데이터 `LabActorCap`·`LabHydrateM`, `lab_config`의 `actor_cap=`·`hydrate_m=`.
- 빌드·작은 실행 끝: `Scripts/build.ps1` 성공. `-Small`은 `q2crowd`(기본, 그리고 `-LabActorCap=1000 -LabHydrateM=50`)와 `-Stage M3 -Variant m3mass`가 모두 종료 코드 0, `respawns=43 kills=8 snipes=39`(Q3과 같다). 개발 확인 1만 P1 15초 두 번(아래 "개발 확인")에서 새 스탯이 찍혔다.
