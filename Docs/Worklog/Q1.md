# Q1 체력 분산

개체마다 체력을 60\~240 균등으로 준다([ADR-0009](../Decisions/0009-flat-scenario-quality-by-distance.md), [measurement.md](../Guides/measurement.md) "품질 계획에서 바뀌는 값"). 목적은 오브 주변에 일관된 시체 고리가 생기지 않게 하는 것이다.

## 진행

- 조사 끝: 체력이 정해지는 곳, 피해 곡선, 일련번호 확인(아래).
- 구현 끝: 체력 함수 하나(`FLabConfig::HealthFor`)와 디버그 인자 `-LabHealthFixed=`.
- 빌드 끝: `Scripts/build.ps1` 성공.
- 작은 실행 끝: 단계마다 종료 코드 0(아래).
- 전후 비교 끝: 스크린샷 두 장과 초당 사망 수(아래).
- 커밋 끝: 푸시하지 않음.

## 조사

체력을 정하던 곳은 세 군데이고 모두 상수 `FLabScenario::MinionHealth`(100)였다.

- 액터 단계 M0\~: `ALabMinion::InitMinion`(`LabMinion.cpp`). 인자로 받는 `InSerial`이 있다. 스포너가 `NextSerial++`로 준다(`LabCrowdSpawner.cpp:204, 225`).
- Mass 새 엔티티: `ULabCrowdSubsystem::SpawnEntities`(`LabCrowdSubsystem.cpp`)의 생성 직후 초기화. `Serials[i]`가 있다.
- Mass 풀 재사용: `ULabCrowdSubsystem::ReinitPooledEntity`. 같은 `Serial` 인자를 받아 일련번호를 새로 넣고 있어 체력도 같은 값으로 다시 받는다.
- 리스폰은 둘 다 같은 경로를 지난다(액터: 스포너의 `SpawnAt`, Mass: `RequestRespawn` → `SpawnEntities`).
- `FLabUnitTypeParams::MaxHealth`(`LabMassTraits.cpp:34`)는 공유 조각에 담기기만 하고 읽는 곳이 없다. 공칭값 100으로 둔다.

일련번호를 둘 곳이 둘 이상이지 않았다. 모든 경로에 이미 일련번호가 있어 체력은 (시드, 일련번호)의 순수 함수로 두면 된다. 그래서 설계를 묻지 않고 구현했다.

### 오브 피해 곡선

두 경로가 같은 식이다.

- 액터: `ALabOrb::Tick`(`LabOrb.cpp:112-128`).
- Mass: `ULabRangeDamageProcessor`의 처리(`LabMassProcessors.cpp:449-453`).

식은 `Closeness = 1 - d / ZoneRadius`, `dps = Lerp(ZoneDpsEdge, ZoneDpsCenter, Closeness) * dt`이고 `ZoneRadius` 800cm, 가장자리 100, 중심 300(`LabConfig.h`)이다. 거리 d에 대해 선형이다(`dps(d) = 300 - 25 * d[m]`). 개체가 3m/s로 직진하면 `dps(t) = 100 + 75t`이고 누적 피해는 `100t + 37.5t²`다. 코디네이터의 계산(선형 증가)이 코드와 맞는다. 사망 거리는 체력 60\~240에서 8m 가장자리 기준 대략 3.4\~6.5m다(누적식으로 푼 값, 계산값).

## 구현

- `FLabScenario::HealthMin = 60`, `HealthMax = 240`(`LabConfig.h`). 범위는 이 두 상수뿐이다.
- `FLabConfig::HealthFor(Serial)`(`LabConfig.cpp`): `Seed ^ (Serial * 0x9E3779B1)`에 murmur3 마무리 혼합을 거쳐 24비트로 \[0, 1)을 만들어 범위에 편다. 같은 시드·일련번호면 같은 값이고, 소형·대형이 같은 범위다.
- 호출 세 곳: `InitMinion`, `SpawnEntities`, `ReinitPooledEntity`.
- 디버그 인자 `-LabHealthFixed=<값>`: 0보다 크면 모든 개체가 그 값이다(분산 전 재현, 100). 켜면 `lab_config`에 `health_fixed=`가 붙고, 기본 실행의 로그는 그대로다.
- 저격은 건드리지 않았다(즉사 그대로, `Snipe()`는 체력을 보지 않는다).

## 빌드와 작은 실행

- `Scripts/build.ps1`: 성공(경고만, 기존 `DoesArchetypeHaveTag` 폐기 경고).
- `Scripts/run-dev.ps1 -Small -Stage <단계>`(N=100, 20초): M0, M1, M2, M3, M4, M5(`m5bounds`, `m4offpool`) 모두 종료 코드 0. 단계마다 `kills=8 respawns=43 snipes=39`로 같다(N=100에서 죽음이 8개뿐이라 단계 사이 일치를 확인하는 값으로만 쓴다).

## 전후 비교(참고: Development 빌드 `-game`)

조건: M5 `m5bounds`, 2종, P1, N=5000, 200초 실행 뒤 QHD 스크린샷(195초), 시드 20261106. 전은 `-LabHealthFixed=100`(분산 전 체력), 후는 기본(60\~240). 라벨 없는 개발 확인 실행이다.

| | 체력 100 고정(전) | 60\~240 분산(후) |
| --- | --- | --- |
| 200초 누적 사망(`kills`, 저격 제외) | 5,730 | 5,710 |
| 초당 사망(누적 ÷ 200초) | 28.7 | 28.6 |
| 재생성 수(`respawns`) | 6,146 | 6,124 |
| 평균 프레임(`avg_ms`) | 8.9 | 9.1 |

초당 사망 수는 분산 전후로 달라지지 않았다(0.4% 차). 사망 수는 도착 흐름이 정하고 체력은 죽는 자리만 옮기기 때문이다(개체가 오브까지 걸어 들어오는 만큼 죽는다). 이 값은 두 실행을 한 번씩 돈 것이라 잡음 범위는 모른다. `avg_ms`도 Development 값이며 비교에 쓰지 않는다.

스크린샷(같은 시드, 같은 카메라):

- 전: [p1-health100.jpg](../../Measurements/Q1/shots/p1-health100.jpg). 시체(붉은 개체)가 오브 둘레에 반원 하나의 띠로 모여 있다. 죽는 자리가 한 곳(약 5.7m)이라 생기는 고리다.
- 후: [p1-health60-240.jpg](../../Measurements/Q1/shots/p1-health60-240.jpg). 시체가 오브 가까이와 바깥쪽으로 폭넓게 흩어지고 띠의 모양이 흐려졌다. 시체 더미가 겹겹이 놓여 한 줄의 고리로 읽히지 않는다.

한계: 한 장면 한 장씩 눈으로 본 것이다. 시체 위치 분포를 수치로 재지 않았고, 대형이 시체를 가려 오브 뒤쪽은 보이지 않는다. 고리가 "완전히 풀렸는지"는 사용자가 두 장을 보고 판단한다(measurement.md는 안 풀리면 확정값을 다시 받는다고 적었다). 내 눈에는 고리가 풀렸다기보다 폭이 넓은 띠로 퍼진 것으로 보인다.

## 마무리

바꾼 파일: `Source/HordeOptLab/LabConfig.h`, `LabConfig.cpp`, `LabCrowdSubsystem.cpp`, `LabMinion.cpp`, 이 문서, `Measurements/Q1/shots/` 스크린샷 둘.

확인하지 못한 것:

- 체력 분포가 실제로 60\~240 균등인지 로그로 세지 않았다(해시 식만 검토). 시체 거리 분포도 재지 않았다.
- 액터 단계 M0의 체력 분산 효과는 스크린샷으로 보지 않았다(작은 실행으로 종료 코드와 사망 수만 확인).
- Test 패키지는 다시 만들지 않았다. 체력이 바뀌어 이전 묶음의 값과 이어 비교할 수 없으므로 총괄 묶음에서 전 단계를 다시 잰다.
- `FLabUnitTypeParams::MaxHealth`는 공칭값 100 그대로다(읽는 곳 없음).
