# M5 작업 기록

## 설계 조사 (2026-11-11, 코디네이터, 읽기만)

엔진 소스와 MetaHuman Crowd 플러그인을 읽고 M5(원거리 표현 VAT ISM → ISKM) 구현 전에 정할 것을 모았다. 결정은 코디네이터가 사용자에게 하나씩 묻고 [plan.md](../plan.md) "M5"에 적는다.

줄임말: **MR** = `Engine/Plugins/Runtime/MassGameplay/Source/MassRepresentation`, **ENG** = `Engine/Source/Runtime/Engine`, **MHC** = `Engine/Plugins/MetaHuman/MetaHumanCrowd/Source`. ISKM = `UInstancedSkinnedMeshComponent`. ASTPD = `UAnimSequenceTransformProviderData`(ISKM이 재생할 클립 목록 에셋). 트랙 = ASTPD 안에서 인스턴스 하나에 배정되는 재생 슬롯(클립, 시작 시각, 재생 속도). `m4offmove` = M5의 기준점(200m 밖 Off 밴드 + Lab 이동 프로세서).

### 직접 확인한 두 가지

- **우리 코드는 사망한 엔티티를 파괴하고 새로 만든다**(`Source/HordeOptLab/LabMassProcessors.cpp` 677\~689행, `Context.Defer().DestroyEntities` + `RequestRespawn`). plan.md "M5"의 "M1부터 재활용으로 짜면 여기서 바꿀 것이 없다"는 전제는 사실이 아니다.
- **ISKM 트랙은 파괴된 엔티티마다 하나씩 샌다.** 할당은 `MR/Private/MassVisualizationComponent.cpp` 773·864행(`AllocateTrack`), 해제는 1156행(`DeallocateTrack`)뿐이다. 해제 입력을 채우는 `RemoveInstance`는 `FMassStaticRepresentationTag`를 요구하는 정적 경로(`MassStationaryISMSwitcherProcessor.cpp:30,127`, `MassStationaryISMRepresentationFragmentDestructor.cpp:28,91`)에서만 불린다. 움직이는 인스턴스는 그 프레임에 갱신되지 않으면 인스턴스만 지워지고 트랙과 트랙 맵 항목은 남는다(`:812-827`). 같은 엔티티 핸들을 엔티티 풀링(파괴하지 않고 다시 쓰기)을 하면 기존 트랙을 다시 쓴다(`:763-770`). engine-notes.md 43행의 파일 위치(`MassUpdateSkinnedMeshProcessor.cpp`)는 틀렸고 `MassVisualizationComponent.cpp`가 맞다.

### 엔진 ISKM Mass 경로(서브에이전트 조사, 줄 번호는 미검증)

- 표현 종류는 Trait의 `Params.LODRepresentation`이 고른다. ISM 설명자와 ISKM 설명자를 한 Trait에 같이 둘 수 있다(`MR/Public/MassVisualizationTrait.h:28,32`, 등록 `MassVisualizationTrait.cpp:98-123`, 전환 `MassRepresentationProcessor.cpp:351-365`). ISKM 컴포넌트는 메시 설명자 해시마다 하나다(`MassVisualizationComponent.cpp:1012-1019,1305-1337`).
- 설명자 기본값이 우리 VAT와 다르다: `bCastShadows=false`(`MassSkinnedMeshRepresentationTypes.h:79`, VAT ISM은 `true`, `LabCrowdSubsystem.cpp:82`), `AnimationMinScreenSize=0` → `r.Skinning.DefaultAnimationMinScreenSize` 0.1(`Renderer/Private/Skinning/SkinningSceneExtension.cpp:113-116`). 30\~200m 개체는 화면이 작아 애니메이션이 멈출 수 있다. MetaHuman Crowd는 -1(항상 재생, `MetaHumanMassRepresentationSubsystem.cpp:200,211`).
- 엔진 프로세서 둘: `UMassUpdateInstancedSkinnedMeshProcessor`(위치, 보이는 청크만, 정적 태그 제외, 게임 스레드, `MassUpdateSkinnedMeshProcessor.cpp:23,42-54,76`. 우리 `DefaultMass.ini`에서 꺼 둠)와 `UMassConsumeInstancedSkinnedMeshAnimationProcessor`(`FMassRepresentationAnimationFragment` 요구, 청크 필터 없음, `MassRepresentationAnimationProcessor.cpp:27-35`). 두 결과는 같은 배열에 순서로만 맞춰 쌓이는데(`MassVisualizationComponent.cpp:704-754,1460-1475`) 쿼리와 청크 필터가 달라 순서 일치가 보장되지 않는다.
- 엔진은 `SetAutoPlayData`를 시퀀스 번호가 바뀔 때만 다시 부른다(`:766-769,857-860`). 같은 클립에서 시작 시각만 바꾸면 반영되지 않는다.
- 지금 프로젝트: ISM은 엔진 표현 경로(`UMassMovableVisualizationTrait`, `LabCrowdSubsystem.cpp:77-89`)로 만들고, VAT 프로세서가 엔진 ISM 갱신 대신 돈다(`HordeOptLab.cpp:32-34`). ISKM 프로세서와 함께 켜면 충돌하는 곳: VAT 프로세서가 표현과 무관하게 `PrevTransform`·`PrevLODSignificance`를 쓴다(`LabVatProcessor.cpp:170-171`). 액터 준비 대기 중 `PrevRepresentation` 고정(`MassRepresentationProcessor.cpp:119-121,291`)을 엔진 ISKM 갱신은 처리하지 않아 2프레임 빈다(VAT 프로세서는 처리, `LabVatProcessor.cpp:117-119`). Lumen 제외 처리가 ISM 컴포넌트만 훑는다(`LabCrowdSubsystem.cpp:212`).

### 에셋

- ASTPD는 스켈레탈 메시 하나에 묶이고 클립 목록을 가진다(`ENG/Classes/Animation/AnimSequenceTransformProviderData.h:979-988`). 2종이라 두 개(걷기, 피격, 죽기). `UAnimBank`는 필요 없다. 스켈레탈 메시에 인스턴싱 플래그는 없다. 머티리얼에 `bUsedWithInstancedSkinnedMesh`가 필요하다(`ENG/Public/Materials/Material.h:903`). 죽기 색은 액터가 컴포넌트 `CustomPrimitiveData`로 바꾸므로(`LabMinion.cpp:304`) ISKM은 인스턴스 커스텀 데이터를 읽는 변형 머티리얼이 필요하다(지원: `MassVisualizationComponent.cpp:698-703`).
- 애니메이션 바운드는 쿡할 때만 만들어진다(`AnimSequenceTransformProviderData.cpp:716-735`, 런타임 `NewObject`는 바운드 없음 `:402-405`). MHC도 빌드 시점에 에셋으로 만든다(`MHC/MetaHumanCrowdEditor/Private/MetaHumanCrowdEditorPipeline.cpp:110-136,1995-2002`). 그래서 `bake-vat.py`처럼 Python 커맨드렛이 맞다. `set_editor_property("sequences")`가 되는지는 실행으로 확인한다.

### 애니메이션 구동과 30m 전환

- 자동 재생 트랙의 기준 시각은 `WorldTime − Position/PlayRate`, 루프는 `Fmod`(`.h:225-236,460-493`). 시계는 `World->GetTimeSeconds()`(`.cpp:611-621`)로 우리 `Now`와 같다. `Position = Now − StateStartTime`이면 VAT의 무상태 식과 위상이 같다. 크로스페이드 `BlendTime`(`.h:120-122`), `SetAutoPlayData`(`.h:1076`)는 public이다.
- 맞출 것: 액터 시작 시각을 걷기 루프로 감을 때 지금은 VAT 클립 길이를 쓴다(`LabActorSyncProcessor.cpp:162,230,248`). ISKM은 `GetSequencePlayLength`(`.h:926`)로. 풀에서 다시 나온 개체가 이전 생의 걷기 트랙을 받으면 시퀀스 번호가 같아 위상이 갱신되지 않는다.

### MetaHuman Crowd(참고만, 복사 금지)

`../unreal-horde-references/MetaHumanCrowdSample`은 비어 있어 엔진 플러그인 MHC의 C++을 읽었다. LOD High 액터 / Medium 저품질 액터 / Low ISKM / Off 없음(`MetaHumanMassCrowdVisualizationTrait.cpp:23-26`), 거리 Base 0/5/10/50m, Visible 0/10/50/100m(`:34-42`), 상한 10/20/500(`:44-47`), 히스테리시스 20%(`:49`), `bKeepActorExtraFrame`(`:29`). 애니는 속도로 대기·걷기를 고르고 `BlendTime` 0.25초(`MetaHumanMassSimpleAnimationProcessor.cpp:51-62`). 공유 위상 트랙 풀(`MetaHumanMassSharedAnimTrackPool.h:13-33`)은 테스트에서만 쓰인다.

### 위험(5.8.4)

트랙 누수, 프로세서 둘의 배열 순서, 애니 화면 크기 0.1, 그림자 기본 꺼짐. 비 Nanite ISKM은 `r.GPUSkin.UseSceneExtension`(기본 1)이 필요하다(`ENG/Private/SkeletalRenderGPUSkin.cpp:109-115`). Nanite 메시에서 Nanite 스킨이 꺼져 있으면 일반 스켈레탈 프록시로 떨어진다(`InstancedSkinnedMeshSceneProxyDesc.cpp:50-58`). 스켈레탈 메시는 원래 Lumen 장면 밖이다(engine-notes.md).

## 측정 세션

### 1단계: 묶음 러너 (2026-11-11)

`Scripts/run-m5-all.ps1`(42회, `-DryRun`으로 확인, 예상 약 90분)을 `run-m4-all.ps1` 구조 그대로 썼다. 로그 `Saved/Lab/m5-all.log`, 기록 `Measurements/M5/batch-runs.csv`, 끝에 summarize·spikes. 라벨 접두사 `M5-`, 모두 `-Types 2`. 트레이스는 넣지 않았다.

순서: r0 warm(`m5iskm` 20k P1, 버림) → start A/A(`m5iskm` 20k P1 ×3, 태그 start) → main(조건 P1 10k, P1 30k, P2 20k, P1 20k 순서로 `m4offpool` ×3 → `m5iskm` ×3) → 참고(20k P1 `m5blend`·`m5minss`·`m4offmove` ×3, 실행 단위로 섞음) → 끝 A/A(태그 aa) → E5 (b)(20k P1 `m5iskm`·`m5destroy` 각 1회, 태그 `leak`, `-LabDuration=960`을 `-ExtraArgs`로 전달).

단계: `m4offpool`·`m4offmove`는 `-LabStage=M4`, 나머지는 `M5`.

**메타데이터 검사:** m4-all의 검사(`labtypes=2`, M4·M5 단계는 `labsimlod`가 `-`가 아님)에 M5 단계는 `Scripts/check-iskm.py`로 `Lab/IskmInstances` 중앙값이 0보다 커야 한다는 검사를 더했다(0이거나 열이 없으면 멈춤).

**다른 파일:** `run-bench.ps1` Variant ValidateSet에 `m4offpool`, `m5iskm`, `m5destroy`, `m5blend`, `m5minss`를 더했다. `summarize.py`는 런별 열 `gpu_mem_p50`·`gpu_mem_first`·`gpu_mem_last`(`GPUMem/LocalUsedMB`), `iskm_tracks_first`·`iskm_tracks_last`(`Lab/IskmTracks`), `iskm_instances_p50`(`Lab/IskmInstances`)를 더했고(first/last는 측정 앞·뒤 10% 프레임 평균), 태그 `leak`은 조건 이름에 `-leak`을 붙여 비교 조건과 따로 요약한다.

**코드 세션이 맞춰야 할 점 (2026-11-11 현재 `LabConfig.cpp`에 M5 변형·단계가 아직 없다):**
1. `-LabStage=M5`와 변형 `m4offpool`, `m5iskm`, `m5destroy`, `m5blend`, `m5minss`를 파싱하고 `[labvariant]`를 같은 이름으로 쓴다. `m4offpool`은 M4 단계에서 엔티티 풀링이 켜진 `m4offmove`여야 한다(러너는 `-LabEntityPool`을 붙이지 않는다. 변형·단계로 코드가 정한다. 다르게 하려면 알려 달라).
2. 스탯 이름은 `Lab/IskmTracks`, `Lab/IskmInstances`(plan.md 그대로)여야 `summarize.py`·`check-iskm.py`가 읽는다. 다르면 알려 달라.
3. M5 단계의 `labsimlod` 메타데이터는 `-`가 아니어야 한다(`m4offmove` 구성).
4. `-LabBench`에서 `-LabDuration=960`이 측정 시간을 960초로 늘리는지 확인이 필요하다(`LabConfig.h`의 설명은 "개발용 -Small 실행"). 벤치 모드가 이 값을 무시하면 E5 (b)가 16분이 되지 않는다.
5. `m5destroy`도 `Lab/IskmInstances`가 0보다 커야 검사를 통과한다.

2단계(실행)는 코디네이터의 "시작" 뒤.

| 2 | 죽기 | `Death_A` | 2.1333초 | 64 | `Death_A` | 0.6333초 | 19 |

**스켈레탈 메시를 복제한 이유.** ASTPD는 통합 본 맵이 없는 메시를 거부한다(`AnimSequenceTransformProviderData.cpp:475-481`). 통합 본 맵은 LOD 빌드 설정 `bOptimizeForInstancing`을 켜야 생긴다(engine-notes.md 14절). 설계 조사 "에셋"의 "스켈레탈 메시에 인스턴싱 플래그는 없다"는 틀렸다. Fab 원본 메시에 켜면 액터 경로의 렌더 데이터도 다시 빌드돼 이전 단계의 측정 조건이 바뀌므로, 복제본(`SK_…ISKM`, LOD 5개 모두 켬)에만 켰다. 스켈레톤은 원본과 같아 클립을 그대로 쓴다. 이 복제는 대안을 비교한 결정이라기보다 "측정 인프라와 이전 단계를 건드리지 않는다"는 규칙을 따른 것이라 ADR을 쓰지 않았다.

**머티리얼.** 액터 머티리얼(`bake-vat.py` `make_actor_material`)과 같은 그래프다: Diffuse × lerp(UnitTint, DeadColor, DeadAmount), 노멀, 거칠기 0.6. 색 값은 `Scripts/lab_unit_colors.py`(소형 UnitTint 흰색·DeadColor (0.6, 0.06, 0.05), 대형 (0.15, 0.15, 0.18)·(0.132, 0.0132, 0.011)). 사용처는 SkeletalMesh와 InstancedSkinnedMesh를 둘 다 켰다(ISKM 프록시가 둘 다 검사한다, `SkeletalMeshSceneProxy.cpp:229-240`). 복제 메시의 머티리얼 슬롯(1개)에도 이 머티리얼을 넣었다.

**커스텀 데이터 번호.** DeadAmount는 **인스턴스 커스텀 데이터 0번**(`PerInstanceCustomData` DataIndex 0, 기본값 0)이다. 뜻은 액터의 `CustomPrimitiveData` 0번과 같다(0 = 산 개체 색, 1 = 죽기 색, 그 사이는 섞음). 코드 세션은 액터에 쓰는 값을 그대로 ISKM 인스턴스 0번에 쓰면 된다.

- ISKM 컴포넌트의 메시는 **복제본 `SK_…ISKM`**이어야 한다. ASTPD의 `SkinnedAsset`이 복제본이고, 컴포넌트 메시와 다르면 ASTPD가 등록을 거부한다(`AnimSequenceTransformProviderData.cpp:468-473`). 액터는 지금처럼 Fab 원본 메시를 쓴다.

- 머티리얼은 복제 메시 슬롯에 이미 들어 있다. 설명자에서 머티리얼을 덮어쓸 필요가 없다. 덮어쓴다면 `M_…ISKM`을 쓴다(VAT 머티리얼과 액터 머티리얼은 ISKM 사용처가 없다).
- `NumCustomDataFloats` = 1, 0번 = DeadAmount(액터 `CustomPrimitiveData` 0번과 같은 값).
- 대형 배율(`[Lab] LargeScale` 2.0)은 에셋에 굽지 않았다. 인스턴스 트랜스폼에 곱한다(VAT와 같다).
- 애니메이션 바운드는 Test 패키지에서 런타임에 확인한다(위).
- `[LabUnitAssets]` ini 키는 만들지 않았다(`Config/`는 코드 세션 소유). 경로는 위 표.

### 남은 문제와 갈림길(추천안으로 정한 것)

- **종류가 안 맞는 풀 엔티티.** 종류(소형·대형)마다 아키타입과 ISKM이 달라 풀 엔티티는 같은 종류의 일련번호만 받는다. 남은 것은 세워 둔다. 2000 P1 30초에서 풀 대기 10개였다. 대기 수는 "죽은 대형 수 − 태어난 대형 수"의 누적이라 개체 수 안에서 오르내리고 계속 늘지 않는다고 보았다(긴 실행에서 `lab_iskm_stats pooled=`로 확인할 것). 다른 안(엔티티의 종류를 바꾸기)은 아키타입·표현 핸들을 함께 바꿔야 해 버렸다.

### `m5bounds` 변형 (2026-11-11)

"트레이스 검토"의 실험이다. `SendAllEndOfFrameUpdates` 증가분(약 +1.0ms) 안의 인스턴스별 `CalcBounds` 반복이 원인인지 가른다. `m5bounds`는 `m5iskm`에 ISKM 컴포넌트 고정 바운드만 더한 변형이다. 엔진은 고치지 않았다. `lab_config`에 `iskm_bounds=0/1`을 붙였다.

**구현.** `ULabCrowdSubsystem::ApplyFixedIskmBounds`가 오브 틱마다 부르는 `ExcludeVisualsFromLumen`에서 ISKM 컴포넌트를 처음 찾을 때 `SetPrimitiveBoundsOverride` + `UpdateBounds`를 부른다. 상자는 오브 중심 XY ±245m(`FarCm × 1.1` 히스테리시스 220m + 카메라 15m + 여유 10m), Z −5\~+15m다. 오브는 움직이지 않는다. 인스턴스가 들어온 뒤 컴포넌트의 실제 `Bounds`가 이 상자와 같을 때 컴포넌트마다 한 번 `lab_iskm component=… bounds_override=1 instances=… half_xy=… identity=…`를 남긴다(Test에서도 남는다).

**좌표계.** 월드 좌표다. `UpdateBounds`는 `CalcBounds(컴포넌트 변환)`을 부르고, 그때 `InverseTransformBy(GetComponentTransform().Inverse() * LocalToWorld)`가 항등이라 값이 그대로 나온다(`InstancedSkinnedMeshComponent.cpp:1249-1253`). 로컬 바운드(`LocalToWorld` 항등)는 컴포넌트 변환이 항등일 때만 같은 값인데, 실행 로그가 `identity=1`이다.

**고정 바운드가 닿는 곳(소스 확인).** 비교는 성립한다고 판단했다.

**크기.** 20k P1 묶음의 프레임 p50 차이 +1.65ms는 Game +0.77ms와 프레임 − Game 간격 +0.9ms로 나뉜다. 트레이스에서 크기가 맞는 구간은 다음과 같다. 트레이스 값이라 원인을 가리는 데만 쓴다.

**소스로 확인한 것**
- `EndVisualChanges`의 ISKM 경로는 갱신되는 인스턴스마다 트랙 맵 조회, `GetSequenceIndex`·`GetPosition`·`GetPlayRate` 읽기, `ResolvedAnimStates` 해시 쓰기를 한다(`MassVisualizationComponent.cpp:756-800`). **확인하지 못한 것**

**다음 실험 후보.** `UInstancedSkinnedMeshComponent::SetPrimitiveBoundsOverride`로 고정 바운드(오브 중심 그리는 거리)를 주면 인스턴스별 `CalcBounds` 반복이 사라진다. 코드 몇 줄이고 엔진을 고치지 않는다. `EndVisualChanges` 쪽은 엔진 수정 없이 줄일 길이 보이지 않는다.
