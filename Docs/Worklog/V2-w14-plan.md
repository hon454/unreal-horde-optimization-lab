## 0. 용어

- 프레임 p50, 프레임 p95: 한 실행의 측정 창(180초)에서 프레임 시간의 50번째, 95번째 백분위수다. 글과 README에서도 이 이름을 그대로 쓴다(사용자 지시 2026-11-17). 정의는 아래 "용어 규칙"을 따른다.
- 표의 값: 같은 조건 세 실행의 중앙값이다. 출처는 `Measurements/Full4/summary.csv`이고 따로 적지 않으면 호드 총수 1만, 오브 시점 카메라(P1)다.
- 이동: 오브가 반지름 57.3m 원을 2m/s로 도는 장면이다(라벨 `V0-`). 정지: 오브가 원점에 서 있는 장면이다(라벨 `V1-`).
- 기법별 기여: 최종 구성(단계 8)에서 기법 하나를 끄고 잰 조건과 단계 8의 차이다. 옛 문서와 조건 표는 같은 것을 "빼 보기"(`ablation`, `a8*`)라고 부른다. 이 계획안은 사용자가 정한 새 이름을 쓴다(결정 7).
- 최대 N: 프레임 p95가 16.7ms를 넘기 직전의 호드 총수다. 잰 총수 사이를 로그 보간한다. 기능 미달(`UNMET`) 점은 보간에서 뺀다([measurement.md](../Guides/measurement.md) "실패 등급").
- 구별되지 않음: 중앙값의 차이가 두 조건의 범위 중 큰 쪽보다 작거나, 0.5ms 아래다. `Full4`에는 5회 묶음이 없어 0.5ms 아래 차이는 범위를 넘어도 이렇게 쓴다([measurement.md](../Guides/measurement.md) "차이 판정").
- 비용을 줄이는 단계, 표현을 더하는 단계: 조건 표의 성격이다. 비용을 줄이는 단계는 2, 3, 5, 8이고 표현을 더하는 단계는 4, 6, 7이다([v2-plan.md](../v2-plan.md) "사다리").
- 계획안의 작업 단위 이름은 `W14-<번호>`다(12절).

용어 규칙(글과 README):

- posting.md 56행은 새 용어를 처음 나올 때 한 문장으로 정의하라고 한다. 같은 문서 57행은 "프레임 p95"를 풀어 쓰라고 한다. 사용자 지시로 57행의 그 부분이 바뀐다.

#### 결정 1. 글을 몇 편, 어떤 주제로 쓰나

- 지금 상태: `v1`은 사다리 단계마다 한 편, 열 편이었다. 사용자가 전면 재작성을 허락했다. `Full4`의 단계 4\~7은 하나씩은 구별되지 않는다(프레임 p95 +0.06, +0.31, +0.19, +0.46ms). 단계 3에서 7까지를 합치면 +1.02ms로 구별된다(14.15 → 15.17ms, 범위 13.98\~14.27과 15.09\~15.43).
- 추천: 여덟 편(3.2절). 표현을 더하는 단계 4·6·7을 한 편으로, 비용을 줄이는 단계 5·8과 기법별 기여 전체를 한 편으로 묶는다. 엔진에서 찾은 문제를 따로 한 편 둔다.
  - 얻는 것: 글마다 구별되는 결과가 하나씩 있다. 단계 4\~7의 "구별되지 않음"이 묶음 안의 한 문장이 되고 묶음 전체의 +1.02ms가 결론이 된다. 작업 세션이 여덟 개다.
  - 잃는 것: README 단계 표와 글이 1:1로 맞지 않는다. 글 04는 기법 셋을 다뤄 "배경 지식" 절이 상한(셋 안팎, 1,000자)에 붙는다.
- 대안 A: 단계마다 한 편(00, 단계 1\~8, 요약의 열 편).
  - 얻는 것: README와 사이트의 단계 표가 글과 1:1이다. 기법마다 배경 지식이 넉넉하다.
  - 잃는 것: 넷이 "구별되지 않음"이 결론인 글이다(posting.md "핵심 발견에는 시각 자료가 반드시 하나"를 채우기 어렵다). 세션이 열 개다.
- 대안 B: 다섯 편(00 목표와 재는 법, 01 액터에서 Mass로(단계 1·2), 02 직접 짠 분리(3), 03 품질과 기법별 기여(4\~8), 04 요약과 엔진에서 찾은 문제).
  - 얻는 것: 일이 가장 적다(세션 다섯).
  - 잃는 것: 03과 04가 4,000자를 넘거나 배경 지식을 줄여야 한다. 엔진 문제가 요약 뒤에 묻힌다.

- **05**: 단계 8의 두 기법(그림자를 다시 켜면 프레임 +0.07, GPU +0.48ms. 고정 바운드를 끄면 +0.98ms). 기법별 기여 막대 하나에 모든 행. 하이드레이션을 끈 조건 −6.98ms와 병목이 GPU로 바뀌는 것, 200m 밖 지우기 +3.54ms, 캡슐 −1.86ms. Simulation LOD와 엔티티 풀은 1만 240초에서 프레임 차이가 없다(트랙 수는 결정 2). 하이드레이션·ISKM·배경 무리를 끈 조건은 함께 빠지는 것이 있다(measurement.md "변수가 둘 이상 섞인 행").
- **06**: 다섯 문제 안팎. ISKM 트랙이 늘 때 이전 뼈대 슬롯이 깨지는 번쩍임(engine-notes 42절, ADR-0018), ISKM 트랙 제공자가 가산 클립을 그대로 자세로 쓰는 것(46절), 움직이는 ISKM의 트랙 누수와 엔티티 풀(3절 표), 게임 스레드 전용 쿼리의 쓰기 선언 때문에 작업자 스레드를 기다리는 것(47절), Chaos 라인 트레이스가 캡슐 정면 평면 위의 시작점을 놓치는 것(53절). Budget Allocator와 URO(52절)는 01에서 다룬다.
- **07**: 단계 3에서 처음 목표 안에 들었고, 4\~7이 품질에 약 1ms를 썼고, 8이 그만큼 되찾았다. 자원: 드로우 콜 9,075(단계 1) → 2,928(단계 2) → 1,956(단계 8), GPU 메모리 9,253 → 3,356 → 3,363MB. 참고 두 점: 정지 장면 단계 8 11.46ms, 탑뷰 6.23ms(프레임 p95, 이동과 직접 견주지 않는다). 여유 2.47ms(16.7 − 14.23). 한계 다섯(6절).
