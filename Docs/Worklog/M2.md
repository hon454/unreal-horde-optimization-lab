# M2 작업 기록

## 2026-11-08 설계 결정과 VAT 구현 (-LabStage=M2)

- 결정 세 가지를 선택지와 추천을 놓고 하나씩 정했다(사용자). (1) 가까운 구간도 M3 전까지 같은 VAT ISM으로 그린다. 처음 계획의 High = None은 그리는 개체 수가 바뀌어 변수가 둘이 된다. (2) 대표 설정은 200m 밖도 그리고, 지우는 효과는 E2 (c)에서 따로 잰다. (3) VAT ISM 프로세서는 엔진 `UMassUpdateISMProcessor`를 상속하고, 엔진 것과의 교체는 `-LabStage`로 시작 때 정한다(M1은 엔진 경로 그대로).
- engine-notes.md의 "상속하지 말고 뒤에 도는 별도 프로세서"에는 근거가 없었다. City Sample은 상속해 한 반복에서 위치와 커스텀 데이터를 쓰고 엔진 것을 ini에서 끈다. 커스텀 데이터는 위치와 같은 순서로 쌓여야 하므로 별도 프로세서는 순서가 어긋날 위험이 있다.
- AnimToTexture 굽기는 데이터 에셋의 텍스처를 미리 만들어 두어야 한다(없으면 조용히 넘어간다). 변환한 정적 메시의 라이트맵 UV 생성을 꺼서 VAT용 UV 채널 1과 겹치지 않게 했다. 머티리얼 그래프는 Python `MaterialEditingLibrary`로 만들었다(MCP 연결 안 됨). 원본 Paragon 머티리얼의 마스크·발광은 옮기지 않아 금속 광택이 M0보다 덜하다.
- 엔진 VAT 머티리얼의 AutoPlay는 fmod로 반복 재생해 한 번 도는 피격·죽기가 끝에서 튈 수 있다. AutoPlay를 끄고 프레임을 CPU가 태그와 남은 시간으로 계산해 넘겼다(커스텀 데이터 Frame, PrevFrame). 걷기 위상은 일련번호로 흩었다.
- `SetShouldAutoRegisterWithGlobalList`는 에디터 빌드에서 `Config/DefaultMass.ini`에 값을 쓴다(`MassProcessor.cpp:255-270`). 쿡 커맨드렛도 게임 모듈을 올려 값을 썼다. 패키지에는 영향이 없었지만 리플렉션으로 CDO 값만 바꾸게 고쳤다(b5868cd).

## 2026-11-08 E2 측정 (M2-mass-*, M2-noanim-*, M2-vatvert-*, M2-vatcull*-*, M2-vatdie*-*, M2-kill*-*)

- `Scripts/run-e2.ps1` 64회, 1시간 26분, 실패 0(패키지 c867446). M1을 같은 묶음에서 재려고 `run-bench.ps1`에 `-Stage`를 더하고 변형 이름 `noanim`(mass와 같음)으로 M2 폴더에 남겼다. `summarize.py`는 그룹을 태그로 나누지 않아 M1 폴더에 태그로 넣으면 지난 M1 수치와 섞였다.
- `summarize.py`의 라벨 정규식이 변형 이름의 숫자를 받지 않아 `vatdie0`·`vatdie1k`가 빠졌다. 정규식만 고쳤다.
- (a) VAT 비용은 Game Thread(인스턴스마다 커스텀 데이터 쓰기)에서 나왔다. P1 GPU는 그대로였고 P2(탑뷰, 다른 GPU 비용이 작다)에서만 GPU가 늘었다. 50k P1 프레임은 M1 실행 하나가 39.1ms로 튀어 범위가 넓어 구별되지 않았다.
- (d) 첫 설계는 "사망 0"에서 범위 피해와 저격까지 꺼서 아무도 죽지 않고 5천 명이 오브에 쌓였다(GPU 14.1ms). 사망 비용이 아니라 밀집을 쟀다. 평소 시나리오에 초당 1천 명을 더하는 `kill0`/`kill1k`로 다시 쟀다(패키지 b5868cd). 치명 발생기는 피격·사망 중인 개체가 많아 걷는 개체 수로 나눠야 기대 건수가 맞았다.
- 같은 M1이 묶음에 따라 20k 16.0(E1, 96f8202) / 15.2(E2, c867446)로 달랐다.
